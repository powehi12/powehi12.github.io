ClinEnv

前言

标题：ClinEnv: An Interactive Multi-Stage Long Horizon EHR Environment for Agents
论文链接：https://arxiv.org/abs/2606.02568 （arXiv:2606.02568v1，2026-06-01 提交，20 页 / 6 图 / 12 表）
代码与数据：GitHub 开源代码 + PhysioNet 托管数据（需先通过 PhysioNet 的合规认证才能使用）
作者单位：Georgia Institute of Technology、北京大学、UT Southwestern Medical Center、清华大学（一作 Yuxing Lu，通讯 May D. Wang）

标签：EHR 交互式环境；长程序贯决策；确定性本体打分；过程质量评测

摘要：这篇论文的核心思想说白了就一句话——别再让大模型做选择题了，让它当一回住院部的主治医生：病人的信息不会主动摆在它面前，它得自己去问病人、问护士、开化验、查既往病历，问完之后必须在"开什么药、做什么操作、下什么诊断"上做出不可撤销的决定，然后拿真实病历里医生当时的实际操作来对答案。具体做法是从 MIMIC-IV 里把每次住院自动切成一串按时间排序的"决策阶段"（全自动，无需人工标注），每个阶段搭一个由四个专职 agent（患者/护士/化验/既往史）组成的信息环境，模型必须先主动查询再提交决策；评分同时打两套分——结果分用 ATC 药物本体和 ICD 层次结构做确定性匹配，过程分则衡量信息覆盖率、查询效率、化验浪费金额和用药日成本。最终得到 3,509 个 case、9,297 个决策阶段、26,043 条 ground-truth 决策，七个模型跑下来最强的 GPT-5.4 也只有 0.306 的 decision F1，而且诊断（0.51）远好于管理决策（0.17），结果质量和过程质量严重脱钩。

Step 1：论文解读

1：为什么说现有的医疗 benchmark 全都不够用

作者开篇的态度非常明确：临床工作不是从给定选项里挑一个答案。真实的住院场景有三个静态题库根本碰不到的性质——信息是不完整的、必须主动去找；决策是序贯的、而且泼出去的水收不回来；每个决策横跨用药、操作、诊断三类，最后要拿病人真实的病程来验证。

1.1：四类前作各自的"结构性妥协"

作者把前人工作分成四类，逐个点名批评，逻辑相当干净：

  • 知识型（MedQA、MedMCQA、PubMedQA、MMLU-Health、MultiMedQA）：把"临床能力"等同于"知识检索"，既没有信息获取，也没有不确定下的承诺。
  • 数据交互型（EHRSQL、MIMIC-SQL、FHIR-AgentBench、MedAgentBench）：把 EHR 当成一个可查询的数据库，评的是 SQL/API 调得对不对。任务是原子化的、外部预先指定好的，所以测的是"数据访问技能"，而不是"判断哪些数据重要、这些数据该导向什么行动"的临床推理。
  • 问诊对话型（AgentClinic、MedDialBench、MAQuE、HELPMed、AMIE）：用 LLM 扮演病人。这一派的贡献是确立了交互式评测的重要性，但天花板被它自己的模拟器锁死了——ground truth 上限就是喂给模拟器的那点东西（通常是考试 vignette），而中间过程只能靠 LLM-as-judge 去评自由文本对话。
  • 代码执行型（MedAgentGym、MedCalc-Env）：类比 HumanEval/SWE-bench 做可执行环境，但评的单位是代码和公式，不是临床决策本身。

1.2：锐评——这张对比表是"为自己量身定做"的

作者在 Table 1 / Table 7 里列了 5~7 个设计维度，然后展示只有 ClinEnv 全勾。这是 benchmark 论文的经典操作：维度是自己选的，选完当然只有自己全满足。比如"自动构建"这一维度，对 MedAgentBench 打 ✗ 是因为它是医生手写任务——可人家手写恰恰是为了保证任务的临床合理性，在这张表里反而成了减分项。这种"把别人的设计取舍重新编码成能力缺失"的写法，OpenReview 上是会被抓的。不过话说回来，"真实 EHR 轨迹 + 多阶段 + 主动求证 + 确定性打分 + 成本指标"这五条同时满足，确实此前没人做到，卡位是站得住的。

2：核心范式 Longitudinal Inpatient Simulation（纵向住院模拟）

论文给自己的范式起了个名字，简称 LIS。拆开看就是五件事凑在一起：真实 EHR 纵向轨迹、多阶段序贯决策、跨异质来源的主动信息获取、基于医学本体的确定性打分、带成本意识的过程指标。

通俗理解：可以把 ClinEnv 想成"医疗版的 SWE-bench，但是加了迷雾"。SWE-bench 给你一个 GitHub issue 和整个仓库，你写补丁跑测试；ClinEnv 给你一个病人，但病历本是锁着的，你得一句句问出来，然后你开的医嘱会被拿去和当年那位主治医生真实开的医嘱做本体级别的比对。

3：数据底座——把 MIMIC-IV 压成一条事件时间线

3.1：预处理是纯确定性的，不碰 LLM

底座是 MIMIC-IV v3.1 + MIMIC-IV-Note v2.2。做法是按 subject_id 和 hadm_id 把结构化表和临床文书拼成一条住院级时间线：入院记录、化验和微生物、医嘱与给药、ICU 监护记录、出入量、操作事件、ICD 编码、出院小结、影像报告，全部打平成"事件"。

关键的工程细节是时间戳的优先级回退：按 charttime → starttime → admittime → chartdate → stoptime → endtime 的顺序取第一个可用的时间作为 canonical event_time，然后按时间、来源表、原始行序做确定性排序（保证 tie-break 可复现）。每个事件都保留 source_table 溯源字段。这一步的产出规模很吓人：24,760 个病人、229,482 个住院时间线文件、约 2.378 亿条事件。也就是说 ClinEnv 最终用的 3,509 个 case 只是从这个池子里采样出来的一小撮，扩展空间极大。

3.2：锐评——这里其实是本文最有复用价值的部分

论文正文对预处理着墨很少，全塞进了附录 B，但对想做 EHR agent 的人来说，这条"MIMIC-IV → 统一事件时间线"的管线本身比 benchmark 更值钱。它是无 LLM 的、确定性的、带溯源的，任何人拿去改造成自己的环境都能用。作者把它当成边角料，我认为是低估了。

4：自动造题流水线——五个阶段（Phase A~E）

这是全文技术含量最集中的地方，核心目标是：不用任何人工标注，把一次住院自动变成一串可评测的决策题。规划骨干用的是 Claude-Sonnet-4.6。

4.1：Phase A 决策抽取

读出院小结，把整次住院期间"主治级别"的决策全抽出来，标注类型（用药/操作/计划）。如果没有完整的自由文本出院小结，就退化成拼接四个章节：主诉、现病史、住院经过简述、出院诊断。

4.2：Phase B 时间锚定（本文最巧的一步）

抽出来的决策是"什么时候做的"？这一步用一个顺序前向滑窗 agent 来定位。设时间线有 T 个事件，从上一个决策的锚点之后开始，给 LLM 一个宽度为 W 的窗口（实现里 W=20），LLM 有 mark_single 和 mark_range 两个工具可用；标中了就记录锚点 $a_i$ 并把下一个决策的搜索起点推到 $a_i+1$，没标中就窗口整体前移重试，走到头还没找到就判定该决策"未锚定"。这个顺序约束保证了出院小结里的叙述顺序被映射成时间线上的严格递增顺序，这是很聪明的一招——它把"LLM 定位"这个不可靠操作，用单调性约束给硬性收紧了。只能锚定到入院前事件的决策会被丢弃。

4.3：Phase C 阶段构建与三道过滤

阶段 k 的上下文窗口定义为"上一阶段结束+1"到"本决策锚点-1"，也就是模型能看到的，只有做出这个决策之前的证据。三个安全阀值得注意：

  • 如果没有上下文窗口（前一阶段直接顶到锚点）就跳过；
  • 如果这个药在上下文里已经是在用的活跃药，就跳过——防止"常规续方"被误当成一次真实决策；
  • 上下文事件少于 10 个的阶段，会被合并进相邻阶段，避免出现几乎无信息的决策点。

还有一个叫 leakage expansion（泄露扩展） 的处理：找到锚点后，会往前后各扫最多 10 个事件，把同一药物/操作的相邻记录一并吸收进锚点区间，防止"答案"以证据的形式提前出现在上下文里。这一步做得很细，是防泄露的关键。

4.4：Phase D 诊断可落地性扫描

每次住院最后都会追加一个"最终诊断阶段"，但出院 ICD 码里有很多是历史合并症、跟本次住院八竿子打不着。作者用重叠滑窗（窗口 100、步长 50）扫全时间线，只有被至少一个窗口确认"在本次住院中有证据或被主动管理"的 ICD 码，才会进入最终诊断的 ground truth。

4.5：Phase E 分类与确定性富化

先用 LLM 把决策分成 medication / procedure / diagnosis / plan 四类，用药决策再细分 action 为 start / stop / switch / adjust（adjust 还可带 increase/decrease 方向）。然后最关键的一句话：ground-truth 字段是从 EHR 里确定性富化的，零 LLM 调用——药名直接读 prescription / pharmacy / eMAR 表，ICD 码直接取对应的编码事件。最终每个阶段是三元组 $S_k = (\mathcal{C}_k, \mathcal{G}_k, \mathcal{A}_k)$，分别是可见事件窗口、结构化答案集、本阶段激活的信息源集合。

锐评：LLM 只负责"这是什么类型"，不负责"答案是什么"——这个职责切分是本文能自称"确定性"的全部底气，也是它比 AgentClinic 那一派硬气的地方。但要注意，Phase A 的"抽哪些决策"和 Phase B 的"锚在哪"仍然完全由 LLM 决定，题目的存在性和位置是 LLM 定的，只有答案的内容是确定性的。论文在附录 D.2 声称三条性质"by construction 得到保证"，但全文没有做任何人工抽检来验证 Phase A/B 的错误率，这在一个宣称零人工标注的 benchmark 里是个明显的窟窿。

5：交互环境——四个信息 agent 与两种模式

5.1：四个专职 agent 各管一摊

四个信息 agent 全部由 GPT-5.4-mini 驱动，各自被限制在一个 readview $\mathcal{V}_a$ 上，也就是 EHR 事件按角色过滤后的投影：

  • 患者 agent：只能看人口学、主诉、现病史、既往史，用大白话回答，看不到任何客观检查数值；
  • 护士 agent：生命体征、出入量、给药记录（MAR）、床旁观察、影像小结、操作事件；
  • 化验 agent：这个设计最有意思——它不被动展示结果，你必须用自然语言点名要什么，它做语义匹配（能处理缩写、CBC/BMP 这类套餐展开、同义词），命中了返回数值/单位/参考范围，没做过的检查返回空；
  • 既往史 agent：只在该患者有既往住院记录时才激活，提供既往出院小结的摘要级和全文级两档。

激活规则也很讲究：只有当某个 agent 的 readview 与当前上下文窗口有交集时才激活它，免得模型对着一个没数据的 agent 空转。

5.2：Direct 模式 vs Interactive 模式

Direct 模式把该阶段的完整事件序列一次性喂给模型，直接提交决策——这是消融基线，用来分离"信息获取能力"和"临床判断能力"。Interactive 模式则是每阶段从零信息开始，每回合只允许一次工具调用，直到模型调用 finalize_decision 或达到 60 回合上限。

5.3：提交接口做了两处强约束（重点看这里）

为了把"临床推理质量"和"输出格式能力"解耦，作者做了两件事：第一，只暴露本阶段 ground truth 中真实存在的那些 submit 工具，不存在的类型完全隐藏；第二，直接告诉模型每种类型需要提交的确切数量 $n_k^{(t)}$。这样一来匈牙利匹配总是在等大的两个集合上做，precision 和 recall 只由匹配质量决定，不受数量错配影响。

锐评：作者的动机（去掉格式混淆）我理解，但这是一个非常重的先验泄露。现实中主治医生面对一个病人，最难的恰恰是"此刻到底要不要下医嘱、下几条、下什么类型"。ClinEnv 把这三个问题全部替模型答完了，只留下"填空题：请给出这 2 个药名"。所以严格说，ClinEnv 测的不是"能不能当主治"，而是"在被告知答案的类型和条数之后，能不能猜中主治当年具体开的那个药"。这个泄露有多大？我认为它是本文 0.31 这个数字最大的向上偏置来源之一——真实开放场景下的分数只会更低。

6：打分体系——结果分与过程分双轨

6.1：结果分：类型内匈牙利匹配

按类型分组（诊断/用药/操作）各自独立做匈牙利匹配（Kuhn, 1955），最大化组内总匹配分，然后拼起来算阶段级 F1（连续 precision/recall 的调和平均）。

6.1.1：用药——action 作硬门 + ATC 层次部分分

action 类型是硬门禁：提交的 action 和匹配到的 ground truth 对不上，不管药名多像都是 0 分，这会逼匈牙利算法优先选 action 一致的配对。action 对上之后才比药名：完全同名给 1.0，否则通过 RxNorm API 解析成 ATC 码，按最长公共前缀长度 $\ell$ 给分——$\ell \geq |c^*|$ 给 1.0，$\ell=5$（化学亚组）给 0.8，$\ell=4$（药理学分类）给 0.6，$\ell=3$（治疗学组）给 0.3，$\ell=1$（解剖学组）给 0.1，其余 0。对 adjust 类决策，如果双方都明确指定了方向且相反，药名分减半（只有一方没指定则不罚）。

6.1.2：诊断与操作——ICD 层次 F1

模型交的是自由文本，答案是结构化 ICD 码，所以先做两步映射：在完整 ICD 词表（ICD-9-CM / ICD-10-CM / ICD-9-PCS / ICD-10-PCS）上用 embedding 检索出 top-15 候选，再用 LLM reranker 选最佳。然后把预测码和答案码各自扩展成"自身 + 全部祖先节点"的集合，算集合层面的 Hierarchical F1：
$$HDF1(\hat{c}, c^) = \frac{2|\hat{\mathcal{A}} \cap \mathcal{A}^|}{|\hat{\mathcal{A}}| + |\mathcal{A}^*|}$$
好处是"猜到了大类但没猜到具体亚型"能拿部分分，符合临床直觉。

6.2：过程分：覆盖率、效率、化验浪费、用药成本

信息覆盖率：对每个激活的角色，让一个 judge 拿着该角色的完整 readview，枚举出其中的关键临床事实集合 $I_a$，再逐条判断这些事实有没有在实际对话里被问出来，算出 $cov_a$，然后跨角色做宏平均。平均下来每个 readview 有 32.8 条关键事实。

效率：光看覆盖率不惩罚"乱问一通"，所以正文给了一个折扣式定义 $eff = cov / \max(1, K/|\mathcal{A}_k|)$，其中 $K$ 是本阶段的信息查询次数。直觉是：一个高效的医生，一个信息源问一句话就该把该问的问完；查询数不超过 agent 数就不罚，超了按冗余程度线性压制。

化验浪费率：每个模型开的化验，通过 embedding 检索 + LLM 重排映射到 CMS 临床化验收费表拿到费用；那些"ground truth 临床图景不支持"的检查算作无谓开销：
$$r_{\text{waste}} = \frac{\sum_{t \in \mathcal{T}{\text{excess}}} \text{fee}(t)}{\sum{t \in \mathcal{T}_{\text{ordered}}} \text{fee}(t)}$$

药品获取成本：药名 → RxNorm CUI → NDC 码 → NADAC 全国平均采购价 $p$；同时 CUI → ATC 码 → WHO 定义日剂量 DDD；单药日均成本 $c = p \times \text{DDD}$，阶段级指标是所有新开药的总日成本。

6.3：锐评——效率指标在正文和附录里是两个公式

这是我在通读时抓到的一个实打实的硬伤：正文式 (12) 写的是 $eff = cov/\max(1, K/|\mathcal{A}_k|)$，而附录 C.7 描述实现时写的是"coverage 乘以 $N/(N+K)$，其中 $N$ 是判定的关键事实数、$K$ 是信息查询次数"。这两个公式的量纲、归一化基准、惩罚曲线全都不一样，而且论文正文专门有一段论证"按信息源数而非事实总数归一化，才能让效率成为独立于覆盖率的一个轴"——附录的实现恰恰是按事实数归一化的，正好是正文明确否定的那个方案。表 5 里报告的 Efficiency 列到底是哪个算出来的，读者无从判断。这不是笔误级别的问题，是核心指标不可复现。

7：几个正文没强调、但决定了结论解读的实现细节

7.1：跨阶段是"教师强制"的，错误不会累积

附录 C.6 里藏着一句极其关键的话：进入新阶段时，前一阶段的信息检索对话会保留，但提交和 finalize 调用会被删掉，然后环境把上一阶段的真实 ground-truth 决策注入上下文，这样后续阶段是基于住院期间真实发生的事情来推理，而不是基于模型早先的错误。

这意味着什么？ 意味着 ClinEnv 的"long horizon"是教师强制（teacher forcing）下的长程，不是真正的自主长程。真实 agent 最致命的失败模式——早期一个错误决策把整条轨迹带进沟里、误差指数放大——在 ClinEnv 里被系统性地消除了。作者的取舍是可以理解的（否则评分会被早期错误污染、模型之间不可比），但论文标题里那个"Long Horizon"因此含金量要打折：它测的是"在给定正确历史的条件下，第 k 步能不能做对"，而不是"能不能独立走完 k 步"。这一点论文正文完全没提。

7.2：最终诊断阶段几乎是"送分题"

附录 G 的表 11 揭示：在多阶段 case 里，98.87% 的首阶段和 99.07% 的中间阶段包含用药或操作类答案，而 89.31% 的末阶段是纯诊断。也就是说 case 的结构是**"一路管理决策 + 最后收一个诊断"**，而诊断分数普遍是管理分数的三倍。所以任何"全阶段平均"的曲线，都会在最后一格神秘反弹——这不是模型"恢复"了，纯粹是题型变了。作者自己意识到了这点并在 6.2 节把最终诊断阶段剔除后单独画管理轨迹，这一步处理是诚实且正确的，值得表扬。

8：锐评总结——这篇工作真正的贡献边界在哪

我的判断是：ClinEnv 的贡献是"评测基础设施"级别的，不是"科学发现"级别的。

它最扎实的东西有三件：(1) 那条从 2.38 亿条事件的原始 MIMIC-IV 到结构化决策阶段的全自动管线；(2) 用 ATC / ICD 层次结构做部分分，替代了医疗 agent 领域泛滥成灾的 LLM-as-judge；(3) 把"信息获取"从一个定性描述变成了覆盖率、效率、浪费率、日成本四个可测量的数字。第 (2) 点尤其重要——医疗 agent 评测长期被 LLM-as-judge 的噪声和不可复现性所困扰，本文提供了一条真正可审计的替代路径。

它最弱的东西是"结论"。0.31 的 F1 被作者反复用作"AI 离临床还很远"的证据，但这个数字同时被四个方向拉扯：向上（提交接口泄露类型与条数、教师强制消除误差累积、末阶段送分题），向下（ground truth 是"当年那位医生做了什么"而非"什么是对的"，临床等效替代方案一律计 0）。这些偏置的量级作者一个都没估计，所以 0.31 这个数只能用来在同一套固定 case 上排序模型，不能用来做任何关于"临床可用性"的绝对判断。论文在 Limitations 里承认了第二点，但用的是"这是任何基于真实 EHR 的 benchmark 的固有属性"来搪塞——固有不等于不可测量，做个医生对照实验就能量化。

Step 2：实验部分

1：实验设置

评了七个模型：GPT-5.4、GPT-5.4-mini、GPT-5.4-nano、Llama-3.1-70B、Llama-3.1-8B、Gemma-3-27B、Gemma-3-12B。闭源模型是在 PhysioNet 要求的零数据保留（ZDR）政策下访问的——这是合规必需，也说明想复现这套评测必须自己申请 ZDR，不能随便调 API。

报告的指标是阶段级宏平均（stage-macro），包括总 F1、诊断/用药/操作三个分项分、覆盖率、效率、平均回合数、化验浪费率、化验支出、日均药费。长程子集定义为至少 3 个决策阶段的住院，占比 49.8%。

锐评：这个模型阵容有个明显的洞——没有任何一个医疗专用模型（如 MedGemma、Med-PaLM 系、HuatuoGPT），也没有任何推理型开源模型（DeepSeek-R1 / QwQ 一类）。一个宣称要衡量"临床准备度"的 benchmark，只测通用模型，结论的适用范围其实很窄。更要命的是没有人类基线——见 Step 3 的意见部分。

2：总体结果——最强的也只有 0.31

GPT-5.4 在所有结果类指标上领先：决策 F1 0.306、诊断分 0.511、操作分 0.379、信息覆盖率 0.430。但离饱和差得非常远。

2.1：结果质量和过程质量彻底脱钩

这是全文最有意思的一组观察。Llama-3.1-70B 拿到了全场最高的用药分（0.101），却同时是覆盖率最低（0.140）、回合数最多（14.1）、化验浪费率最高（35.8%）的模型。而 GPT-5.4-nano 完全是它的镜像：准确率有竞争力，回合数最少（4.4），浪费率最低（4.1%），用一半的查询量达到了 GPT-5.4 大部分的覆盖率，反而是信息效率最高的模型（0.281 vs GPT-5.4 的 0.274）。

通俗地说：Llama-70B 像一个话痨实习医生，问了一大堆，开了一堆没用的检查，但偶尔蒙对药名；nano 像一个话少但精准的住院医。只看终点准确率，你根本看不出这两个是完全不同的临床行为模式——这正是作者要论证的核心。

2.2：锐评——但这个"脱钩"的统计基础太薄了

论证很漂亮，证据链有点单薄。Llama-70B 用药分 0.101 对比 GPT-5.4 的 0.097，这个 0.004 的差距完全在噪声范围内，论文没给任何置信区间或显著性检验，却用它撑起了"最好的用药分属于最差的过程"这个反直觉叙事。同样，nano 的效率 0.281 对 GPT-5.4 的 0.274 也只差 0.007。用两个不显著的差异去讲一个强故事，是这一节最大的问题。

3：长程退化——每个模型无一幸免

所有模型在 ≥3 阶段的 case 上都比全集分数低，GPT-5.4 从 0.306 掉到 0.235。附录表 12 给出了细账：绝对跌幅在 0.029~0.072 之间，相对跌幅 14.4%~23.4%，同时每个模型的交互轮数都在增加，其中 Llama-3.1-70B 增加最多（+4.0 轮），但多出来的交互并没有换来更好的覆盖率或更低的浪费。

3.1：真正的瓶颈不是"看不到信息"

作者做了一个很关键的解剖（Figure 2，且只在管理阶段上画）：决策 F1 随阶段序号单调下降，GPT-5.4 从第一个管理阶段的 0.21 掉到第四个阶段的 0.03 以下，其余模型齐齐趋近于零。但同时，覆盖率对 GPT-5.4 基本持平、对弱模型甚至随病历变长而上升——信息是拿到了的。塌掉的是效率：GPT-5.4 的查询数从约 4 次涨到每阶段 50 多次，而覆盖率始终停在 0.45 附近，说明后期全是不产生新信息的冗余提问。

结论是：后期的瓶颈是临床推理，不是信息获取。这个 dissociation（分离）确实是只看终点指标的评测抓不到的，是本文最有说服力的一个发现。

3.2：锐评——50 次查询 vs 60 次上限，这条曲线撞天花板了

正文说 GPT-5.4 后期查询数超过 50，而 Interactive 模式的硬上限是 60 回合。当查询数逼近上限时，"F1 掉到 0.03"到底是模型判断力崩溃，还是模型被强制截断、还没问完就被迫交卷？ 论文没有报告各阶段的截断率（hit-the-cap rate），这两个解释在数据上无法区分。要坐实"临床推理是瓶颈"这个结论，最直接的实验是把上限放到 150 再跑一遍，或者直接看 Direct 模式（信息全给）在深层阶段的表现——论文虽然定义了 Direct 模式，却从头到尾没有报告任何 Direct 模式的结果。这是本文最令人费解的缺失：一个专门为"分离信息获取与临床判断"而设计的对照组，做了却不报。

4：信息获取与浪费——覆盖率越高，反而越省钱

Figure 3 展示了一个反直觉的关系：覆盖率与化验浪费呈负相关，问得越到位的模型浪费越少。GPT-5.4 位于"高覆盖低浪费"的理想角落，Llama-70B 和 Gemma-27B 落在对角（低覆盖 + 35% 以上浪费），而 GPT-5.4-nano 以中等覆盖率取得了全场最低的约 4% 浪费率——说明高效的信息获取不需要靠模型规模堆出来。

作者的解释很到位：覆盖率和浪费率不是两个独立的轴，而是同一种能力（知道什么信息值得去拿）的两面。知道该找什么的模型，既能捞到相关证据，也不会去开临床图景不支持的检查。

4.1：为什么弱模型会浪费这么多钱

Table 6 的"Lab miss"列给出了机制层面的答案：弱模型 6073% 的化验点名的是本阶段根本不存在的检查项，而 GPT 系只有 1119%。也就是说浪费不是因为"多开了检查"，而是因为开的检查名字都对不上——化验 agent 对不存在的项返回空，模型再换个说法接着试，钱就这么烧掉了。

同时，所有模型的信息来源分布都是偏的：每个模型都最爱问护士、最少问化验，GPT-5.4 覆盖了 0.89 的护士事实，但只覆盖 0.25 的化验事实。这个偏好很值得玩味：护士 agent 是"你问什么它都能答一点"的宽泛来源，而化验 agent 要求精确点名。模型在偷懒，捡软柿子捏。

5：诊断能认出来，管理做不对

这是全文最重的一个发现。在纯诊断阶段上模型表现尚可（池化 0.40，GPT-5.4 达 0.51），但在管理阶段 F1 塌到 0.13，差距约三倍，且对每个模型都成立。一句话：认出病人得了什么病，比决定拿它怎么办容易得多。

5.1：用药是最极端的情况

所有模型判对 action 类型（start/stop/switch/adjust）的比例在 53%~73% 之间，但用药匹配分最高也就 0.10 上下。门禁基本过了，说明残余误差全在药物身份上——模型能提出一个合理的治疗类别，但很少能命中治疗组当时实际选用的那个具体药物，ATC 部分分把这个距离如实反映了出来。Llama-8B 的 action 准确率最高（0.73）却是用药分最低之一（0.082），进一步坐实了"难在选药，不在选动作"。

5.2：多问信息救不了这个

在阶段层面，覆盖率与决策 F1 基本不相关（整体 Pearson r=0.08，GPT-5.4 内部 r=0.04）。翻译一下：你把病历翻烂了也不会更知道该开哪个药。

5.3：锐评——这里有一处自相矛盾，而且相当致命

正文 6.4 节说阶段级覆盖率与 F1 基本不相关（r=0.08）；附录 G 却说"跨表 5 的七个模型级数据点，覆盖率与决策 F1 强相关（r=0.865）"。

这不是矛盾，而是典型的生态学谬误 / 辛普森悖论：模型之间"越强的模型覆盖率越高、F1 也越高"，但在同一个模型内部，多覆盖一点并不会让这次决策变好。问题在于，论文没有点破这一点，反而在附录里把 n=7 的 r=0.865 当作"过程指标有效"的正面证据来用。n=7 的相关系数本身就极其脆弱（拿掉 GPT-5.4 一个点，这个 0.865 大概率就散了），何况它和正文的核心结论方向相反。审稿人会直接问：你到底想论证覆盖率有用还是没用？

6：数据侧的两个补充观察

Figure 4 显示 ClinEnv 的诊断分布被慢性住院合并症主导（高血压、高脂血症、GERD、糖尿病），而用药和操作决策则分散得多。Figure 5 则给出一个有价值的相关性：决策密度随时间线变长而下降（Pearson r = -0.365, p < 0.001），说明更长的住院是"每个决策附带更多上下文"，而不是简单地"决策更多"。

锐评：这条 Figure 5 的观察其实和长程退化的解释高度相关，但作者没把两者接起来。长程 case 变难，到底是因为"步数多了"（真长程推理难），还是因为"每步要读的上下文多了"（单纯的长文本大海捞针）？这是两个完全不同的能力，也是两条完全不同的改进路线。用 Figure 5 的密度变量做一次分层分析就能拆开，论文放着现成的数据没做。

Step 3：other

1：重点

第一，本文最有价值的思想是"把临床决策的验证锚定到医学本体上，而不是锚定到 LLM 裁判上"。 用 ATC 层次做药物部分分、用 ICD 祖先集合做 Hierarchical F1、用匈牙利算法做类型内最优匹配，再叠加 action 硬门禁——这一整套让"临床决策对不对"第一次变成了一个确定性的、可审计的、跨论文可比较的数字。医疗 agent 领域此前被 LLM-as-judge 的噪声折磨了太久，这套方法论的价值远超 ClinEnv 这一个 benchmark 本身，任何做医疗 agent 的人都应该把它抄过去当评估工具。

第二，"信息获取"被拆成了可测量的两个正交事实：拿得全不全（覆盖率）和拿得省不省（效率/浪费率），而它们共同指向同一种底层能力——知道什么信息值得去要。 覆盖率与化验浪费的负相关，以及弱模型 60~73% 的化验点名落空，共同说明"多问"和"会问"是两件事。这给临床 agent 的优化目标提供了一个比"准确率"具体得多的靶心：高覆盖、低浪费的那个角落。

第三，最重要的实证结论是那个"分离现象"：随着病程推进，信息覆盖率保持甚至上升，但决策质量单调塌陷。 这直接否掉了当下医疗 agent 最流行的一条改进路线——"给它更长的上下文、让它检索更多的病历"。数据说得很明白：瓶颈在于临床判断，不在于信息通路。配合"诊断 0.51 / 管理 0.17"这个三倍差距，可以得出一个对整个领域都成立的判断：当前 LLM 的医学能力集中在"识别"，而不在"处置"；而所有主流 benchmark 恰好测的都是识别。

2：意见

没有人类专家基线，使得本文所有的绝对数字——以及建立在这些数字之上的全部结论——都无法解释。

论文的核心叙事是"最强模型只有 0.31 F1，说明只看结果的 benchmark 严重高估了临床准备度"。但 ClinEnv 的 ground truth 是"当年那位主治医生实际做了什么"，而不是"什么是正确的"。在这种设定下，一位没有参与过该次住院的主治医生，在同样的信息环境里、被同样告知了决策的类型和条数，能拿多少分？ 我的判断是这个数字会显著低于 1.0，而且很可能落在 0.4~0.6 这个区间——因为"用哪个 PPI、哪种铁剂、哪个喹诺酮"在很大程度上取决于本院处方集、当班药师习惯和当时的库存，而不取决于临床推理。论文自己在附录 F 里给了最好的反例：模型提交了硫酸亚铁，答案是葡萄糖酸亚铁——任何一位医生都会说这两个是等效的，但在 ClinEnv 里这只能拿 0.8 的部分分；而用药分整体只有 0.10 这个"惊人"的数字，恰恰主要由这一类等效替代所贡献。

也就是说，本文最重的那个结论（"管理决策 0.13，模型远未准备好"）是建立在最不可解释的那个指标之上的。作者在 Limitations 里承认了"临床上合理的替代方案可能被判为错"，然后用一句"这是任何基于真实 EHR 的 benchmark 的固有属性"就翻篇了——但"固有"不等于"不可测量"。哪怕只请 2~3 位主治医生在 50 个随机抽取的 case 上跑一遍完整流程，得出一个哪怕很粗糙的人类上界，整篇论文的说服力都会是另一个量级：0.31 相对于人类的 0.55 是"追平了一半"，相对于人类的 0.95 才是"远未准备好"。在没有这个数之前，本文只能支持"模型 A 比模型 B 更接近这家医院当年的实际处置"，而不能支持任何关于临床准备度的判断——而后者恰恰是标题、摘要和结论里反复主张的东西。

3：相关工作

MedAgentGym（arXiv:2506.04405） 是这篇论文在"可执行环境"路线上的最直接对照，同样出自 May D. Wang 组，因此可以看作是同一团队的路线延伸。它提供了 跨 129 个类别的 7.2 万个任务实例，覆盖 MIMIC-III 和 eICU 上的 SQL 查询、计算器式推理、数据分析代码生成，定位是 SWE-Gym 的训练时对应物。它和 ClinEnv 的根本差别在于评测单位：MedAgentGym 评的是模型产出的代码和公式对不对，ClinEnv 评的是临床决策本身对不对。对算力受限的研究者来说，MedAgentGym 的规模更适合做 RL 后训练，而 ClinEnv 更适合做纯评测——两者其实是互补的，"在 MedAgentGym 上训、在 ClinEnv 上评"是一条自然的组合路线。

MedAgentBench（NEJM AI 2025） 代表了"数据交互"路线的最高完成度：300 个医生手写任务、覆盖病历审阅/下医嘱/结果检索等 10 个类别、作用于取自 Stanford STARR 的 100 份患者档案，环境暴露的是与现代 EMR 系统一致的 FHIR 兼容 API，成功与否由操作后的数据库状态判定。ClinEnv 批评它的点是"任务是原子的、预先指定的，而不是从纵向患者管理中自然涌现的"。但反过来看，MedAgentBench 的 FHIR 接口和医生手写任务在临床有效性上比 ClinEnv 的全自动流水线更有保障，而且它不需要 PhysioNet 的 MIMIC 认证门槛。如果目标是快速做出一个能落地的 EHR agent 原型，MedAgentBench 的工程贴近度更高；如果目标是研究长程序贯决策，ClinEnv 才是对的靶子。

MedDialBench（arXiv:2604.06846） 是"模拟患者"路线上最新的一步，走的方向和 ClinEnv 恰好相反。它在问诊 case 上叠加了 24 种参数化的对抗性患者行为，也就是让病人隐瞒、夸大、答非所问，专门测模型在患者不配合时的诊断鲁棒性。ClinEnv 的四个信息 agent 都是完全合作的——问对了就如实给，问错了就返回空，不会撒谎也不会误导。这恰好暴露了 ClinEnv 环境的一个真实缺口：现实住院场景里，护士记录会漏、患者会记不清用药史、化验会有假阳性。把 MedDialBench 的对抗行为参数注入 ClinEnv 的四个 agent，做成一个"不可靠信息源下的长程决策"环境，是一个非常自然、工作量可控、而且明显有增量的后续方向——如果你在找一个可以接着做的题目，这个缝隙我认为是目前最大的一个。

复现

ClinEnv 复现难度评估

先说结论："跑通"不难，"完整复现"很贵，但它可能是目前最值得你投入的一个环境——因为它正好落在你之前纠结的"程序性/序贯决策"那一支上，而且是少数带确定性奖励的医疗 agent 环境。

一、它到底是个什么东西

ClinEnv 把 MIMIC-IV v3.1 + MIMIC-IV-Note v2.2 的真实住院记录自动切成有序的"决策阶段"，模型扮演主治医生，每个阶段必须主动向 patient/nurse/lab/history 四个 agent 提问，然后提交用药、操作、诊断决策。规模是 3,509 例住院、9,297 个决策阶段、26,043 条 ground truth。最强的 GPT-5.4 也只有 0.306 decision F1，其中诊断 0.51、用药 0.097。

二、复现难度拆解（从易到难）

① 数据准入 — 中等阻力，但周期长
benchmark 发布在 PhysioNet，必须先满足 PhysioNet 合规资质。CITI 培训 + DUA 审批通常 2–6 周。这是硬门槛，建议今天就去申请，别等到想跑的时候才发现卡在这。

② 一个容易被忽略的坑：ZDR 合规
论文脚注写得很轻描淡写：闭源模型是在 PhysioNet 要求的 Zero Data Retention 政策下访问的。这意味着你不能拿学生号直接调 OpenAI/Anthropic API 去跑 MIMIC 数据——需要企业级 ZDR 协议或 Azure OpenAI 的合规通道。对研究生这是最实际的障碍，比算力还麻烦。绕开方式：只评本地开源模型（Llama/Qwen/Gemma 系），这条路完全合规。

③ 评测端 API 成本 — 这是真正的大头
算一笔账：GPT-5.4 平均 9 轮/阶段，且后期阶段查询数会爬到 50+ 轮，每阶段上限 60 轮。每一轮信息查询还要触发一次 GPT-5.4-mini 驱动的 agent 应答，再加上 coverage 的 judge 调用、ICD 映射的 LLM reranker。粗算下来评一个模型 ≈ 十万量级的 LLM 调用、10⁹ 量级的输入 token（对话历史每轮重发，成本接近平方增长）。
务实做法：抽 300–500 例跑，方差已经够用了，成本降到 1/10。全量 3,509 例除非你要发榜单，否则没必要。

④ 本地模型推理 — 你的算力约束在这里
论文评了 Llama-3.1-70B/8B、Gemma-3-27B/12B。8B/12B 单卡能跑；27B 要量化；70B 基本要 2×A100 起步。考虑到多轮长上下文，KV cache 压力比一般 benchmark 大。建议只做 7B–14B 档 + vLLM，先把 pipeline 跑通。

⑤ 从 MIMIC 原始表重建整条构造 pipeline — 不建议做
构造用 Claude-Sonnet-4.6 做 planner，Phase B 用 20 事件滑窗顺序锚定，预处理版本包含 24,760 个 subject、229,482 个 admission 文件、2.378 亿条事件。光 Phase B 一例住院就可能几十次 LLM 调用。除非你要改造构造逻辑（比如换成中文 EHR），否则直接用他们发布的 case 文件。

三、复现不出原数字的风险点（提前知道）

用药打分要走 RxNorm API 解析 ATC；诊断/操作要先用 embedding 检索 ICD 全表 top-15 再让 LLM 重排；lab 成本查 CMS 收费表；药费查 NADAC + WHO ATC/DDD。这一串外部依赖里任何一个版本漂移，分数都会变。你的复现目标应该定成"趋势一致"而不是"小数点后三位一致"。

还有一个明确的文本 bug 可以留意：效率指标在正文 Eq.12 写的是 cov / max(1, K/|A_k|)，附录 C.7 却写成 cov × N/(N+K)。两个公式不等价。复现时以代码为准，这个不一致本身也值得写进你的 report。

四、锐评：值不值得

值得，但理由不是"复现"，是"占坑"。

支持的理由：

  • 它是确定性奖励的交互式医疗环境。用药走 ATC 层级偏序、诊断走 ICD 祖先集 HDF1、Hungarian 匹配——不依赖 LLM judge。这是天然的 RL reward signal，作者自己也在类比 SWE-Gym。你之前担心 RL 后训练不可行，但这里可以先做推理时方法（信息获取策略、记忆压缩、query planner），不碰参数也能出结果。
  • 天花板极低留出的空间巨大：0.31 总分、0.097 用药分。这不是"再刷 2 个点"的赛道，是"随便做点像样的东西就能涨"的赛道。
  • 它已经开始被引用了（比如 MedBench v5 的 related work 里有它），说明社区在接。

需要警惕的：

  • 提交接口泄题。系统会告诉模型每种类型要交多少条，只暴露 ground truth 中存在的提交工具。这等于告诉医生"你现在该开 2 个药"——现实里没有这个信号。这是他们为了让 Hungarian 匹配在等大集合上跑而做的妥协，但也让任务失真了。这是你可以攻的点。
  • "长程"是打折的。每进入新阶段，环境会把上一阶段的真实 ground truth 决策注入上下文，让后续阶段基于真实发生的事而非模型自己的错误。这是 teacher forcing,不是真正的误差累积。所以"long horizon"更像"长上下文",不是"长决策链"。要做真正的序贯误差传播,这里有现成的改造入口。
  • 没有人类基线。0.31 到底是模型差,还是 benchmark 上限本来就低?ground truth 是"主治当时开了什么药",临床等效的替代方案一律算错。作者自己在 Limitations 里承认这衡量的是与真实临床实践的一致性,而非与唯一最优解的对比。补一个小规模医生基线,本身就够写一篇短文。
  • 过程指标仍然是 LLM-as-judge,"确定性"只覆盖 outcome 那一半。

  1. 今天:提交 PhysioNet 认证申请（周期最长,先启动）
  2. 同时:找到 GitHub 仓库确认代码是否真的开放——论文 HTML 里那个脚注是占位链接,我没能验证到实际仓库地址,建议直接邮件问一作 Yuxing Lu（北大未来技术学院博士生,GT-Emory-PKU 联合项目,主页 yuxinglu613.github.io,响应通常不错)
  3. 拿到数据后:先用 Qwen/Llama 7B 档 + 抽 200 例跑通全链路,验证打分器能不能复现
  4. 然后:别急着刷分,先挑上面四个软肋里的一个做改造
