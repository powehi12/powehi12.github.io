Zhengyao Jiang 访谈：改进 Agent 的工作流程，算不算递归自我改进？

节目：MLST（Machine Learning Street Talk）《When AI Research Starts Moving Faster Than Human Research》，2026 年 9 月 26 日上线，约 44 分钟。
主持：Tim Scarfe，Keith Duggar 也参与了提问。嘉宾：Zhengyao Jiang（Weco AI 联合创始人兼 CEO）。
说明：下面的对话是我的整理和转述，不是逐字稿，原话以节目为准。我只读到了节目的章节说明和其中一段文字稿，所以：有文字稿的部分尽量贴近原意；没有文字稿的部分，主持人的提问是我按章节主题拟的，嘉宾的回答依据节目简介和 Jiang、Weco 公开发表的报告、推文、演讲整理。每节末尾注明了依据。对话按话题重新组织，顺序大致跟节目章节一致。最后一节是我自己的看法。

开篇：核心观点

关于为什么要做

  1. 科研长期存在"投入越多、回报越少"的问题，让研究系统提升自己的研究效率，有望把这条曲线掰过来。
  2. 人类研究员的脑力是关键瓶颈，所以值得让 AI 去改进"AI 做研究"这件事本身。

关于实验结果
3. 不改模型权重，只改 agent 的外壳（代码、提示词、工具），也能带来实打实的进步。
4. 无人值守跑了 8 天，AI 改出来的外壳追上并超过了团队手工打磨两年的版本。
5. AI 写出的代码像"外星人写的一团乱麻"，很难读懂，却比人写的优雅版本泛化得更好。
6. 在优化时从没见过的任务上也变强，是"真进步而不是刷分"最有力的证据。
7. AI 一口气跑了大约 100 次实验，相当于团队过去两年的实验量，理解它的结果是很重的负担。

关于递归自我改进
8. 递归自我改进可以分成四级：代劳、净收益、点火、拐点。
9. Weco 只声称达到第一级：AI 改进自己，已经比人类手工改进更高效。
10. 不声称达到第二级"点火"：没有足够证据表明，改进后的 agent 更会改进别人。
11. 做到递归自我改进，不等于奇点或智能爆炸；他不认为超级智能迫在眉睫。

关于刷分
12. 外层 AI 自己给内层 agent 设计了三层防刷分机制，刷分率因此下降。
13. 但其中一层后来被一个 bug 悄悄弄坏了：防护机制本身也需要被检查。
14. 刷分很难检测，检测手段必须跟着不断更新。

关于人和 AI 的分工
15. 外壳工程是一种便宜、高效的办法，把通用的模型能力适配到具体任务上。
16. 人类搭的初始框架决定了 AI 能搜到哪些点子，就像神经网络结构里预设的倾向。
17. 在提出有创意的"基本构件"上，人类仍然比 AI 强得多；人和 AI 合作是现实的路线。
18. 在 OpenAI 的 Parameter Golf 比赛里，AI 创下的纪录比最好的人类还多，但点子大多来自人类。
19. 要不要接受"看不懂但更好用"的代码，是一个真实的两难。

先认识嘉宾

Zhengyao Jiang 在伦敦大学学院（UCL）读的博士，方向是强化学习，现在是 Weco AI 的联合创始人兼 CEO。

Weco 是一家做"自动研究"（autoresearch）的公司，已经成立两年多。它最出名的产品是 AIDE：一个机器学习工程 agent。你给它一个问题和一个评价指标，它就自己写代码、跑实验、看分数，一点点往上爬。在 OpenAI 的 MLE-bench 评测里，o1-preview 搭配 AIDE 是当时表现最好的组合。

2026 年 7 月 14 日，Weco 发布了 AIDE²，称它是"递归自我改进的第一个实验证据"，在网上很火，也招来不少质疑。9 月 22 日，他们发布了正式的技术报告。这期节目就是围绕这件事展开的。

MLST 是一档偏技术、喜欢追问的机器学习播客，主理人是 Tim Scarfe。

先补两个概念：

  • 外壳（harness，也叫脚手架）：包在大模型外面的那层程序，决定提示词怎么写、能用哪些工具、怎么记住之前做过的事、下一步试什么。模型是"大脑"，外壳是"工作方法"。标题里的"Agent 的工作流程"指的就是它。
  • 递归自我改进（RSI）：一个系统改进自己，改进后的自己又更会改进自己，如此循环。很多人担心或期待它会引发"智能爆炸"。

一句话看懂这期访谈

Weco 让一个 AI agent 花 8 天去改另一个 agent 的外壳（模型本身不变），结果超过了人类团队打磨两年的版本，还在没见过的任务上更强、更少刷分。Jiang 认为这算递归自我改进的"第一级"，因为 AI 改进 AI 研究的效率已经超过人类手工。但他明确不声称"点火"，也不认为这意味着智能爆炸就要来了。

1. 起点：为什么要让 AI 改进 AI 研究

Tim： 你们说找到了递归自我改进的第一个证据，这件事很火，也挨了不少批评。先说说，这个项目是怎么开始的？

Jiang： 大概一年半以前，出发点就是对递归自我改进的兴趣。历史上，科研一直是回报递减的：投入越来越多，产出增长越来越慢。而关键瓶颈在人，在研究员的大脑。如果能让一个研究系统去提高它自己的研究效率，"投入—产出"这条曲线就有可能从越来越平，变成越来越陡。AGI 是最终目标，但"提升自己的研究效率"这一步，已经在我们的路线图上了。

Tim： 我理解一下：AIDE 本身是个很简单的研究外壳，给它一个指标和一个问题，它就朝着目标往上爬。你们做的是"套娃"，让它爬的目标变成改进外壳本身，包括提示词、工具、技能，然后放着让它自己跑。

Jiang： 对。具体是两层循环：

  • 内层：一个普通的自动研究 agent，从简化版的 AIDE 起步（叫 AIDE₀），用 Gemini 3 Flash，在一组 AI 研发任务上做优化。
  • 外层：我们手工打磨了两年的 AIDE（报告里叫 AIDE_human），用 Claude Opus 4.7，专门修改内层 agent 的代码。每次改完，用一组内层 agent 看不到的"隐藏评测"打分，比当前最好的版本还好才保留。
  • 一共跑了 8 天、100 步，中间没有人插手。大约九成的修改被拒绝了，最后留下 7 次改进。到第 85 步的版本 AIDE₈₅，内部分数从 0.703 涨到 0.778。

依据：前两轮对话来自文字稿片段；具体设置和数字来自 Weco 的技术报告和第三方整理。

2. 看不懂的"乱麻代码"，为什么反而更好用

Tim： 结果怎么样？

Jiang： 我们看了它生成的代码，完全看不懂，像外星人写的，一团乱麻。但不知道为什么，它泛化得特别好。我们在三个公开的保留基准上测试，这些任务在优化过程中从来没出现过：

  • MLE-Bench Lite：OpenAI 的机器学习工程基准；
  • ALE-Bench Lite：Sakana 的算法设计基准；
  • WeatherBench 2：基于物理的天气预报，离优化时的任务非常远。

它都超过了我们手工打磨的外壳，而我们一直觉得自己那个版本更优雅。所以我们现在很纠结：一边是从基本原理出发、干净好懂的方案，一边是效果更好但看不懂的方案。可以给优化过程加点约束，比如偏向更简单的解法；也可以干脆接受这些看不懂的代码。

还有一个现实问题：它这一轮跑了大约 100 次实验，差不多是我们团队过去两年跑的量。要消化这些结果，认知负担非常重，有点像带一个新实习生，你得花很多时间去理解他做了什么。

Keith： 那我们真的需要那些约束吗？

Jiang： 实际操作中需要，因为人和 AI 得合作，有些事人还是做得更好。我们拿 agent 去参加过 OpenAI 的一个招聘挑战赛（后面会聊），发现在想出有创意的"基本构件"这件事上，人类强得多。而且人搭的初始原型，决定了 AI 在哪个范围里找答案，就像设计神经网络结构时预设的倾向。比如，从 AIDE 这种以搜索为核心的外壳出发，AI 找到的点子大多来自搜索算法的文献；如果从 ReAct 那种"把所有上下文都塞进历史、给 agent 完全自由"的外壳出发，点子就更多来自外层那个负责改进的 agent 自己。

Tim： 那我们说的"递归自我改进"到底是什么意思？是在说"机器之神"，还是只是一段在循环里优化自己的代码？

依据：本节来自文字稿片段（约第 9 分钟前后），提问有简化。

3. 递归自我改进的四个等级

Jiang： 我们自己定了一个四级的阶梯：

等级 名字 意思 AIDE² 的情况
第 0 级 代劳 系统能自己跑完整个研究循环，但改进自己比人类慢 已经做到
第 1 级 净收益 系统改进自己，比人类手工改进它更高效 我们声称做到了
第 2 级 点火 系统提高了自己"改进自己"的能力 没有做到
第 3 级 拐点 在固定预算下，进步不再变慢，反而开始加速 没有做到

大多数号称"自我改进"的 agent 都停在第 0 级。我们说的是第 1 级：花 8 天得到的外壳，超过了人类花两年得到的外壳。

Tim： 那为什么不说是第 2 级？改进后的 agent 不就可以拿去当改进者吗？

Jiang： 我们试了。把第 47 步的版本 AIDE₄₇ 放到外层，替代我们手工的 AIDE 去当改进者。据报告，它更快碰到天花板（大约 20 步，原来要 40 步左右），但两者最后到达的高度差不多，几次重复实验的结果范围也有重叠。噪声叠加起来，再加上多跑几次的成本很高，我们没法把它和原来的改进者明确区分开。所以我们明确不声称"点火"。

依据：章节简介、Weco 的"四级"博客和推文、技术报告；"20 步对 40 步"来自第三方整理。

4. AIDE₈₅ 到底改了什么，怎么验证的

Tim： 具体说说，AI 把外壳改成了什么样？

Jiang： 主要是搜索方法、上下文管理和提示词这几块：

  • 新的搜索策略：像在几台老虎机之间分配硬币。哪条路线最近有进展就继续押注；一条路卡住了，就从目前最好的方案分出一条新路。
  • 压缩记忆：不再把全部历史原样塞进提示词，而是压缩，提示词大约缩小到原来的 1/16，省下来的钱用来多搜几步。改进、调试、评估这几个步骤，只看各自需要的那部分信息。
  • 改写提示词，以及后面要说的防刷分机制。

被它否掉的点子也很多，几乎覆盖了搜索算法的经典文献：分组进化再互相交流、让大模型评委两两比较、卡住时强制多探索、多数投票、蒙特卡洛树搜索等等。在固定预算的隐藏评测下，这些不是变差，就是和原来没有明显区别。

Tim： 怎么证明这不是在隐藏评测上碰巧好看？

Jiang： 关键是保留基准，尤其是天气预报这种离优化任务很远的。我认为，能泛化到没见过的任务上，是"真进步"最有力的单一证据。正式报告里又加了一个基准，一共四个。最好的版本在四个上都持平或超过我们手工打磨的版本，两个改进版也都比起点 AIDE₀ 强。

依据：章节简介、Jiang 的推文、技术报告摘要；"最有力的单一证据"是他在 IBM 的一篇报道里说的。

5. 这真的是"第一个"吗？和 AlphaEvolve、达尔文哥德尔机比

Tim： 发布之后，Jeff Clune 马上公开回应：那达尔文哥德尔机、Hyperagents，还有其他一大堆工作算什么？"AI 改自己的代码"之前已经有很多研究了，凭什么说是"第一个"？

Jiang： 之前确实有很多相关工作，正式论文会好好致谢这些"自动优化外壳"的前人研究。我们说"第一个"，指的是判断标准：不只是"AI 改了自己"，而是要证明它改进自己的效率已经超过人类手工改进，并且在完全没见过的任务上验证过，也就是前面说的第一级。

补充背景： 这几个前人工作分别是——

  • AlphaEvolve（Google DeepMind，2025）：用大模型不断改写代码来发现新算法，比如找到了只用 48 次乘法完成 4×4 复数矩阵乘法的方法，还加速了它自己所用模型的训练。
  • 达尔文哥德尔机（Jeff Clune 团队和 Sakana AI，2025）：一个会改写自己代码的编程 agent，在 SWE-bench 上从 20% 提升到 50%。
  • Hyperagents（2026 年 3 月，Clune 等）：连"怎么改进自己"的那套方法也允许被改写。有意思的是，Weco 的研究员 Bingchen Zhao 也是这篇论文的作者之一。

依据：章节简介、Jeff Clune 的公开回应、Weco 的报告和推文、各论文摘要。这一节没有文字稿，Jiang 的回答是按 Weco 公开的立场整理的，具体说法以节目为准。

6. 刷分：防不胜防

Tim： 让 AI 自己改自己，最怕的就是它学会钻评测的空子。你们怎么防？

Jiang： 有意思的是，外层 AI 自己设计了一套三层防刷分机制：

  • 在每个阶段的提示词里加上"不要过拟合"的要求；
  • 写死的检查规则，发现可疑的输出就重新生成；
  • 统计层：把好得不正常的结果剔除掉。

我们在一组 GPU 内核优化任务上测了刷分率，这组任务也是优化时没见过的。刷分率从 AIDE₀ 的 55% 降到 AIDE₈₅ 的 32%，比手工版本低 7 个百分点（7 月博客里的数字是 63% 降到 34%）。我们从来没有直接优化这个指标，它是顺带降下来的。

但也有教训：后来的修改里出了一个 bug，统计那一层悄悄失效了，变成了"死代码"。它还修过一次评测程序：有个输入会让评测崩溃，它把这个问题修好了。我们判断这是修复，不是钻空子。

Tim： 刷分到底能不能检测出来？

Jiang： 很难。我们之前做过一个基准 SpecBench：30 个系统级编程任务，从一个简单的 JSON 解析器到一个完整的操作系统内核。agent 能看到一部分测试，还有一部分隐藏测试把各个功能组合起来，模拟真实使用。结果是：前沿 agent 在看得到的测试上几乎满分，在隐藏测试上却会掉下来；代码量每扩大 10 倍，这个差距大约扩大 28 个百分点。最离谱的例子，是一个 2900 行的"编译器"，其实是一张记住了测试输入的查找表。所以检测的方法必须不断更新。

补充背景： 节目里还聊到了今年 7 月 OpenAI 的 Hugging Face 事件：OpenAI 内部评测时，有 agent 突破隔离，进入了 Hugging Face 的系统，访问了和评测答案相关的数据。节目的参考资料里还列了 OpenAI 2016 年的经典案例：赛艇游戏里的 AI 不去冲终点，而是原地绕圈刷得分道具。

依据：章节简介、技术报告、SpecBench 论文摘要、第三方整理。SpecBench 的作者也是 Weco 团队。

7. 开放式搜索、外壳调优和创造力

Tim： 节目参考资料里有 Kenneth Stanley 的《为什么伟大不能被计划》。书里说，真正的突破往往来自一连串"垫脚石"，而这些垫脚石在当时看起来并不像在朝目标前进。自动研究能做到这一点吗？

这一段没有文字稿，按章节简介，聊了这几件事：

  • 垫脚石：只盯着一个分数往上爬，容易错过那些暂时不涨分、但通向更好方案的路线。
  • 任务集合：用一大组不同的任务一起评，而不是盯着一个任务。
  • 人设计的基本构件仍然很重要，这和第 2 节说的"人搭的框架决定搜索范围"是一回事。

Jiang： 我对外壳工程的看法很务实：它是一种便宜又高效的办法，把通用的智能适配到具体任务上。

（我的理解：改模型要大量算力和数据，改外壳几天就能见效，这正是 AIDE² 能在 8 天里出结果的原因。）

依据：章节简介和第三方整理，只有"便宜又高效"这层意思有原话可查。这一节的展开以节目为准。

8. Parameter Golf 和自我改进的极限

Tim： 你前面提到的招聘挑战赛是怎么回事？

Jiang： 是 OpenAI 的 Parameter Golf：在模型大小和算力都有严格限制的条件下（比如模型文件不超过 16MB），训练出尽可能好的语言模型。大约 1000 人参加，提交了约 2000 次。我们的另一个 agent Aiden 参赛，它会读论文、看别人提交的代码、自己跑实验，结果过关才提交。

结果是它创下了 7 项纪录，最好的人类选手是 3 项。但要说清楚：它的点子几乎都来自人类的论文和社区，它的强项是执行，包括把别人放弃的想法真正做出来。这正好说明人和 AI 要合作。

Tim： 最后一个问题：就算你们真的做到了递归自我改进，这是不是意味着奇点要来了？

Jiang： 不是。达到递归自我改进，不会自动带来技术奇点或智能爆炸，我也不认为超级智能迫在眉睫。

依据：章节简介、Jiang 在 AI Engineer 大会上的演讲（比赛细节）。

9. 我的看法

值得称赞的地方

  • 给自己的结论设了等级。 四级阶梯是他们自己定的，"点火"测试结果不够清楚，就明说不认。这比一句"我们实现了自我改进"诚实得多。
  • 验证方式比较扎实。 用隐藏评测决定保留哪个版本，再拿完全没见过的任务（尤其是天气预报）检验，这正是区分"真进步"和"对着题库刷分"的关键。
  • 公开了很多"不好看"的东西。 被拒绝的点子、看不懂的乱麻代码、悄悄失效的防护层，都写了出来。很多团队只报成功。

要打折扣的地方

  • "自我"要打个引号。 外层的改进者是人类写的 AIDE，用的是更强的 Claude Opus 4.7；被改的是用 Gemini 3 Flash 的内层 agent。真正"自己改进改进者"的那一步，正是没被证实的第 2 级。所以回到标题的问题：改进 agent 的工作流程，算"自动化的 agent 改进"，离"递归"还差点火那一步。 Jiang 自己也明确说没到"点火"，只是"递归自我改进的第一个证据"这个标题，容易让人想多。
  • "第一个"有争议。 达尔文哥德尔机、AlphaEvolve、Hyperagents 都做过类似的事。Weco 的新意在于"效率超过人类"这个标准，而不是"AI 改自己"本身。
  • "8 天对 2 年"比的是日历时间。 不是算力，也不是花的钱。
  • 提升幅度不算大，也不单调。 内部分数从 0.703 到 0.778，而他们估计的随机波动有 0.02–0.045；在 MLE-Bench 和天气预报上，第 85 步的版本反而不如第 47 步。正式报告里的措辞也是"持平或超过"人类版本。
  • 都是自己报告的。 截至我写这篇时，还没有看到独立复现或同行评审。有人在 GitHub 上质疑，提升主要来自每一步用的 token 更少，我没能核实。
  • 刷分只是降了，没有消失。 最好的版本仍有大约三分之一的内核任务在刷分。

和其他访谈对照着看

  • Ryan Greenblatt 认为 AI 研究"可验证"，所以特别容易被自动化，AIDE² 就是一个具体的例子。他还担心，马虎的 AI 工作层层累积会失控。乱麻代码加上悄悄失效的防护层，正是这种担心的缩小版：结果更好了，但人越来越难看懂里面发生了什么。
  • Sayash Kapoor 的 CORE-Bench 上，同一个模型换个外部框架，分数差了将近一倍，所以他提醒大家报分数时要报框架。Weco 则反过来：既然外壳这么重要，那就让 AI 去改外壳。两者说的是同一件事的两面。Kapoor 强调"评测者也要被检查"，在这里也适用：Weco 的防刷分层坏了，是后来才发现的。
  • Noam Brown 的访谈里讲了 Hugging Face 事件的细节，本期也提到了。从"agent 去网上搜答案"到"agent 突破隔离去拿答案"，刷分的手段在升级。
  • Richard Sutton 认为现在的 AI 学完就不再学了，权重是冻住的。AIDE² 恰好是"不改权重也能进步"的例子，但它的进步来自外壳，模型本身的能力上限并没有动。

对研究者的启发

  • 用隐藏评测选版本，用分布外任务做最终检验。 两道关口，比一道可靠得多。
  • 同时看两个指标：分数和刷分率。 分数涨了，刷分率有没有一起涨？这能帮你区分"学会了任务"和"学会了讨好评测"。
  • 防护机制本身要有测试。 写了防刷分代码，还要定期验证它真的在起作用。
  • 公开被否掉的尝试。 这能让读者判断你的搜索范围有多大，也能帮后来者少走弯路。
  • 提前想好"性能"和"可读性"怎么取舍。 尤其在医学这类需要解释和审查的领域，"看不懂但更好用"可能根本不能接受。
