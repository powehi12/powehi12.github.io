# 前言

标题：MedAgentBoard: Benchmarking Multi-Agent Collaboration with Conventional Methods for Diverse Medical Tasks（NeurIPS 2025 Datasets & Benchmarks Track）
论文：https://arxiv.org/abs/2505.12371
代码：https://github.com/yhzhu99/MedAgentBoard
项目主页（含全部结果、数据与 prompt）：https://medagentboard.netlify.app/
OpenReview：https://openreview.net/forum?id=BPpG4qQaNj
单位：北大 / 港大 / 爱丁堡 / ETH，一作 Yinghao Zhu，通讯 Liantao Ma、Lequan Yu

标签：医疗多智能体；基准评测；EHR 预测建模；临床工作流自动化

摘要：一句话说本质——**吹了两年的"让好几个 LLM 智能体开会诊"，一旦拉上"一个足够强的单模型"和"老老实实微调过的传统小模型"同台竞技，在大多数医疗任务上其实并没有赢。** 这篇论文做的事情很朴素：它认为现有的医疗多智能体评测有两个硬伤——任务太窄（几乎全是选择题式医学问答）、基线太软（只跟单个 LLM 比，从来不跟传统机器学习比），于是搭了一个叫 MedAgentBoard 的擂台，把四类任务（医学（视觉）问答、通俗摘要生成、结构化 EHR 预测、临床工作流自动化）横跨文本 / 医学图像 / 结构化 EHR 三种模态铺开，然后让三条赛道的选手打全场：传统方法（微调 BERT/VLM、XGBoost、GRU、AdaCare 等）、单个 LLM（zero-shot / few-shot / CoT / self-consistency）、多智能体框架（MedAgents、ReConcile、MDAgents、ColaCare、AgentSimp、SmolAgents、OpenManus、Owl）。结论是一张相当扎脸的成绩单：文本医学问答上单个强 LLM 就够了，医学 VQA 和 EHR 预测上传统专用模型还是断层第一（AdaCare 在 MIMIC-IV 死亡预测上 AUROC 94.28% 对 GPT-4o 的 85.99%），多智能体唯一真正站得住脚的主场是临床工作流自动化——而且赢的不是"更聪明"，而是"更能把活干完"。论文最后给出的机制性解释比结论本身更值钱：多智能体只在**任务可分解性高**的场景有效，而在**感知受限**的任务（如 VQA）上，第一步丢掉的视觉细节是后面无论开多少轮会都捞不回来的。

# Step 1：论文解读

## 1：这篇论文到底在跟谁过不去

先说清楚它针对的那股风气。2024 年起，"医疗多智能体"成了热门叙事：让一个 LLM 扮演内科医生、一个扮演放射科医生、一个扮演主任，再让它们互相讨论、投票、辩论，最后收敛出一个答案——听起来非常像真实的多学科会诊（MDT），也非常好写故事。MDAgents、MedAgents、ReConcile、ColaCare 这些工作都报告了正向结果，尤其在医学问答上偶尔能超过单个 LLM。
但作者提出一个很扫兴的问题：这些"超过"是真本事，还是评测设计出来的幻觉？他们把矛头指向两点：

- **任务太窄**：绝大多数评测就是 MedQA / PubMedQA 这类选择题。可真实临床里医生要的是自由文本的诊断支持、要做数据分析、要读结构化的化验单趋势，不是从 A/B/C/D 里挑一个。选择题打得好，不代表有临床效用（论文引了 NEJM AI 那篇《It's time to bench the medical exam benchmark》来撑腰）。
- **基线太软**：几乎所有工作都只跟"单个 LLM"比，绝口不提"传统方法"。而传统方法是在任务数据上真刀真枪微调过的，在准确率、效率、稳定性上很可能还压着 LLM。你不跟它比，等于田径比赛只让自己队内选手互相跑。
  锐评：这两条批评一点都不新鲜，通用领域已经有 MAST（《Why do multi-agent LLM systems fail?》）和《If multi-agent debate is the answer, what is the question?》干过同样的事。MedAgentBoard 的贡献不在于"提出质疑"，而在于**把这套质疑第一次系统地搬进医疗，并且真的把传统方法请回了基线表**。第二点是它最硬的价值——很多医疗 LLM 论文的表格里根本看不见 XGBoost 和 GRU，这在 2025 年是一件相当离谱的事。

## 2：四类任务是怎么挑出来的

作者不是随手抓四个数据集，而是按"医疗 AI 的三类利益相关者"来铺：患者、临床医生、研究者。前两类任务服务患者（把复杂的医学信息变得可读），后两类服务医生和研究者（用结构化数据做决策支持和提效）。

### 2.1：任务一：医学（视觉）问答

考的是"知不知道"。分两个子形态：选择题（考知识回忆和判别推理）和自由生成（考生成能力和细粒度理解）。

- 文本 QA：**MedQA**（USMLE 美国医师执照考试风格五选一）、**PubMedQA**（基于生物医学摘要，有 Yes/No/Maybe 闭式标签，也有原摘要结论当作自由生成的参考答案）。
- 医学 VQA：**PathVQA**（病理切片图，只用其中的 yes/no 二分题）、**VQA-RAD**（临床放射影像，yes/no 题当选择题 + 179 道开放题）。
  每个数据集抽约 200 条测试样本。这里有个不起眼但值得点赞的细节：作者明确说 MDAgents 当年每个数据集只用了 50 条，自己抽 200 条是为了统计可靠性——顺手把前人的样本量问题挂在了明面上。

### 2.2：任务二：通俗摘要生成

考的是"能不能说人话"。把系统评价、研究论文这类专业文本改写成非专业人士读得懂、又不失真的版本。这个任务的难点是双重的：既要真读懂术语，又要在不牺牲关键含义、不引入错误的前提下重新表达。
用了五个数据集：**Cochrane**（系统评价的通俗语言摘要，作者自己写的）、**eLife** 和 **PLOS**（论文 + 作者/编辑写的科普版；eLife 的摘要长度约为 PLOS 的两倍，抽象程度和可读性更高）、**Med-EASi**（细粒度简化标注，众包）、**PLABA**（PubMed 摘要的逐句对齐通俗改写）。每个抽 100 对。

### 2.3：任务三：结构化 EHR 预测建模

考的是"看不看得懂化验单"。两个临床上真有意义的目标：**院内死亡**和**30 天再入院**。数据用 **MIMIC-IV v3.1**（ICU，取 17 项化验 + 2 项人口学，按天合并，住院超 7 天只留最后 7 天、更早的聚合）和 **TJH**（同济医院 485 例 COVID-19 住院患者，73 项化验 + 2 项人口学，公开可下）。每个任务抽 200 名患者。
这里的技术张力最值得注意：结构化 EHR 是**高维、稀疏、带时序、大量缺失**的数值表格，跟自然语言和图像的建模范式完全不同。要喂给 LLM，就得先把它"文本化"——论文用的是按特征展开的列表式 prompt，并且**手工从医学指南里整理了每个特征的单位和参考范围**塞进 prompt 里。这一步是善意的，但也正是后面翻车的伏笔。

### 2.4：任务四：临床工作流自动化

考的是"能不能替我干活"。这是四个任务里最贴近真实科研日常、也是全文最有价值的一块新任务。四个子类型：

1. **数据抽取与统计分析**：从结构化 EHR 里找变量、清洗、变换（细分为 data wrangling / querying / statistics / preprocessing）。
2. **预测建模**：选模型、训练、评估。
3. **数据可视化**：一类是"抽数据+统计+画分布"，另一类是"先定义建模任务、再可视化模型参数或性能"。
4. **报告生成**：把分析结果整合成有结论、有洞见的文档。
   任务是这么造出来的：先用 **Gemini 2.5 Pro** 喂 schema 和数据样本，批量生成一大堆分析问题，再人工审阅筛选，最终留下 **100 道**（MIMIC-IV 50 + TJH 50）。
   锐评：LLM 造题 + 人工筛这套流程现在很常见，但对 benchmark 来说始终是个软肋——题目的难度分布和风格会被出题模型的偏好带走，人工筛只能剔除坏题，剔不掉系统性偏差。而且 100 道题、还要拆成四个子类型，每格的样本量薄到经不起细分分析。

## 3：三条赛道的参赛选手

MedAgentBoard 的核心设计就是让三种范式在同一张表里出现，这也是它跟别的 benchmark 最大的区别。

### 3.1：传统方法（Conventional）

- 文本 QA：**BioLinkBERT**、**GatorTron** 微调成分类器（GatorTron 是拿 HuggingFace 预训练权重加 MLP 分类头再微调）。
- 医学 VQA：**M³AE**、**BiomedGPT**、**MUMC** 微调；**LLaVA-Med**、**Med-Flamingo** 因为已经在大规模医学 VQA 上训过，直接 zero-shot 评，看开箱泛化能力。
- 通俗摘要：**BART**、**BART-CNN**、**T5**、**PEGASUS** 在各数据集上微调。
- EHR 预测：机器学习（决策树、**XGBoost**，只用最后一次就诊）+ 深度学习（GRU、LSTM）+ EHR 专用模型（**AdaCare**、**ConCare**、**GRASP**，吃完整纵向序列）。
  注意一个天生的不对称：这些分类器式的传统方法**做不了自由生成**——它们的答案空间是被限定的词表。所以自由生成那几列，传统方法整行是空的。

### 3.2：单个 LLM

提示策略从简到繁铺了一个梯度：**zero-shot**、**few-shot ICL**（给两个示例）、**CoT**（要求先输出 Thought 再输出 Answer，JSON 格式）、**SC**（self-consistency，跑 5 次多数投票）、**CoT-SC**（CoT + 投票）。
EHR 任务上还额外横向比了一大票模型：OpenBioLLM-8B、Qwen2.5-7B、Gemma-3-4B、HuatuoGPT-o1-7B、DeepSeek-R1-Distill-Qwen-7B（本地 LMStudio 部署）以及 DeepSeek-V3、DeepSeek-R1、GPT-4o、o3-mini-high（走 API）。

### 3.3：多智能体协作

作者把医疗多智能体的协作机制归纳成几类形态：带角色的推理（MDAgents）、讨论（MedAgents、ReConcile）、投票、辩论、模拟 MDT 会诊（ColaCare）。具体落地：

- QA/VQA：**MedAgents**、**ReConcile**、**MDAgents**、**ColaCare**，全部适配进统一 pipeline，agent 之间**只用文本交换**以保证公平。
- 通俗摘要：改编 **AgentSimp**，编排九个角色、实际跑七个的流水线——项目总监定简化准则 → 结构分析师抽关键信息 → 内容简化师出初稿 → 简化监督员审校 → 比喻分析师加类比 → 术语解释员处理术语 → 校对员终审。
- EHR 预测：把它当自由生成 QA 处理，让 agent 就"患者健康状态和风险因素"辩论。**MDAgents 在这个任务被排除**，理由是它那套复杂交互模式和难度判定对结构化数据预测意义不大，退化后跟固定交互的 agent 没区别。
- 工作流自动化：**SmolAgents**、**OpenManus**、**Owl**——这三个是通用 agent 框架，关键是**自带工具调用（能跑 Python）**。
  所有 LLM-based 方法的底座统一是 **DeepSeek-V3-0324**（VQA 的视觉部分用 Qwen-VL-Max；ReConcile 因为设计上要求 agent 多样性，混用 DeepSeek-V3 / Qwen-Max / Qwen-VL 系列）。

## 4：评测怎么打分

三层评估手段，按任务性质分配：

- **确定性指标**：选择题用 Accuracy；EHR 预测用 AUROC + AUPRC（不平衡数据两个都要看，AUPRC 尤其关键）；通俗摘要用 ROUGE-L（内容重合）+ SARI（专门衡量简化质量，看词的增删保留是否恰当）。
- **LLM-as-a-judge**：自由生成 QA 用。VQA-RAD 开放题答案通常就一个词或短语，所以只判二值等价（输出 1 或 0）；PubMedQA 长答案则给 1–10 分的细粒度评分，并且给 judge 也上了 CoT，要求先输出 reasoning 再给 score，最后乘 100 报告。
- **专家人评**：工作流自动化用。**六位 PhD/MD 评估者**（3 位做医疗 AI 的 CS 博士、1 位 MD、1 位生物医学工程、1 位生物统计）对照人工整理的参考答案独立打分、归类错误、再汇总。不是简单二分，而是分出"正确 / 无结果 / 答案错误 / 不完整 / 正确但呈现有问题 / 模型未保存 / 缺指标 / 数值异常 / 可读性差"等一整套细粒度错误类型——这套错误分类法本身就是有用的资产。
  锐评：这套评估设计是全文最扎实的部分，尤其是任务四敢上真人专家、还报了 Fleiss' Kappa。但 LLM-as-a-judge 的底座跟被测模型属于同一家族（DeepSeek 系），self-preference bias 的风险论文没有正面处理。

## 5：和已有 benchmark 相比新在哪

论文用一张表把自己和前人排开（MedHELM、MedAgentsBench、Strategic Reasoning、MAST、Multi-agent Debate、MDAgents）。差异可以简化成两条：

- **横向**：别人评的任务基本落在"医学问答 / 编程 / 数学 / 知识 QA"，MedAgentBoard 是唯一同时覆盖医学（V）QA、EHR 预测、通俗摘要、工作流自动化四类的。
- **纵向**：别人的"Benchmarked Methods"一栏基本是"Single LLM"或"Single LLM + Multi-agent"，只有 MedAgentBoard 写着"Conventional Methods, Single LLM, Multi-agent"。
  更有意思的是这张表顺手暴露了领域内的**结论撕裂**：MDAgents 说多智能体在十个任务里赢了七个，MAST 和 Multi-agent Debate 说多智能体基本赢不过 well-prompted 单 LLM。作者把自己定位成"裁决者（adjudicating conflicting claims）"。锐评：这个定位挺聪明，但也有点自我加冕——一个 benchmark 能不能裁决，取决于它的对照设计是否真的公平，而这一点后面（见 Step 3 意见）恰恰是它最脆弱的地方。

# Step 2：实验部分

## 1：任务一：文本 QA 单模型够用，VQA 传统模型断层第一

先看文本 QA。**LLM 全面碾压传统方法**，而且不是小胜：MedQA 选择题上 BioLinkBERT 只有 32.45%、GatorTron 36.60%，而单 LLM zero-shot 就 77.50%，CoT-SC 冲到 **89.90%**（全场最高）。PubMedQA 选择题上传统方法尚可（BioLinkBERT 70.40%），但仍被所有 LLM 方法压住。
多智能体呢？**有竞争力，但赢不稳**。MedAgents 在 PubMedQA 选择题上 83.85% 是该列最高，但在 MedQA 上 85.25% 输给 CoT-SC 的 89.90%。最扎心的是 PubMedQA 自由生成：**DeepSeek-V3 裸 zero-shot 就拿到 91.23%（LLM-as-a-judge），比所有多智能体都高**，MedAgents 81.63%、ColaCare 81.72%，MDAgents 更是掉到 62.54%。
再看 VQA，画风完全变了。**专用传统 VLM 稳坐第一**：PathVQA 上 MUMC 91.40%、M³AE 90.65%；VQA-RAD 选择题 M³AE 89.05%；VQA-RAD 自由生成 M³AE 71.96%。而通用 VLM 无论单模型还是多智能体都差一大截：VQA-RAD 自由生成里最好的 LLM 方法只有 46.42%，**差距超过 25 个百分点**。
几个值得单独拎出来的现象：

- **ReConcile 在 PathVQA 上崩了**，只有 49.00%——一个 yes/no 二分任务，49% 意味着比随机猜还差一点。多智能体在感知任务上的脆弱性在这里暴露得最彻底。
- **LLaVA-Med 和 Med-Flamingo 这两个"医学多模态大模型"是全表最差的一档**（VQA-RAD 自由生成 19.94% 和 18.38%）。它们打不过 M³AE 这种更小更专的模型，这件事对"医学多模态基座"的叙事相当不友好。
- 锐评：文本 QA 那一栏的传统基线（32%、36%）**弱得不正常**。BioLinkBERT 在 MedQA 上被硬改成五选一分类器，本来就不是它擅长的形态。所以"LLM 碾压传统方法"这个结论在 QA 上其实是被弱基线放大的；真正有说服力的对照是 VQA 和 EHR 那两块。作者把这两种情况混在同一个"传统方法"标签下呈现，读者容易误读。

## 2：任务二：通俗摘要生成，微调小模型继续赢

自动指标上，**微调过的 seq2seq 小模型全面领先**：Cochrane 上 BART-CNN ROUGE-L 42.24%，PLABA 上 PEGASUS 59.11%，eLife 上 BART-CNN 47.08%。而 LLM 这边最好的 Opt.+ICL 在 Cochrane 只有 35.58%，AgentSimp（多智能体）34.25%——**多智能体连单 LLM 的最优提示都没打过**。PLABA 上差距更夸张（41.37% 对 59.11%）。
但这里必须替 LLM 说句公道话，论文自己也承认了：ROUGE 这类指标**天生偏爱风格上像参考答案的输出**，而微调模型正是被显式优化去模仿那个风格的。证据就在 SARI 列里——Cochrane 上 BART-CNN SARI 39.75% 对 LLM 38.56%，差距只有 1.2 个点，比 ROUGE-L 的 6.7 个点小得多。也就是说：**LLM 的简化能力其实不差，差的是"写得像参考答案"**。
另一个有意思的发现：DeepSeek-V3 用最基础的 prompt（Basic 33.65%）跟精心优化的 prompt（Optimized 33.85%）几乎没差别，加了 ICL 才涨到 35.58%。作者顺手引了 DeepSeek-R1 技术报告的说法：模型强了之后，繁复的提示工程边际收益在下降。
锐评：这一节的结论"多智能体不如微调小模型"在方法论上是**最弱的一节**。用 ROUGE/SARI 去评判"通俗性"本身就很勉强——一份读者真正读得懂的科普摘要，完全可能 ROUGE 很低。作者只在讨论里轻轻提了一句指标偏向，却仍然让这个结论进了摘要和 key findings。这里真正需要的是人评或可读性指标（FKGL 之类），而不是继续堆 n-gram overlap。九个 agent 的流水线值不值，这张表其实没有回答。

## 3：任务三：EHR 预测，这是全文最扎脸的一张表

这一节的差距是全文最大的，而且对做 EHR 方向的人来说信息量最密。
**传统方法断层第一**：MIMIC-IV 死亡预测上 AdaCare AUROC **94.28%**、ConCare 94.08%、GRASP 93.14%、LSTM 93.12%、GRU 92.49%；TJH 死亡预测上 AdaCare **99.02%**、XGBoost 98.05%。
**最强单 LLM 有点东西，但不够**：GPT-4o 在 MIMIC-IV 死亡 85.99%、TJH 死亡 95.72%，DeepSeek-R1 在 MIMIC-IV 死亡 83.95%、再入院 73.92%（这是 LLM 里再入院最好的）。对零样本来说确实亮眼，但离 94% 还差近 10 个点。
**AUPRC 才是真正的照妖镜**：MIMIC-IV 死亡预测上 AdaCare AUPRC **81.93%** 对 GPT-4o 的 **42.20%**——差了将近一倍。AUROC 的差距是 8 个点，AUPRC 的差距是 40 个点。这说明 LLM 在**不平衡数据的正类排序**上远远不如专用模型，而这恰恰是临床最在意的能力（你要的是能把真正会死的病人排到最前面）。任何只报 AUROC 的 LLM+EHR 论文，看到这一列都应该冒汗。
**小模型基本是在瞎猜**：DeepSeek-R1-Distill-7B 在 MIMIC-IV 死亡 AUROC **40.94%**——低于 50%，意味着它的预测方向是反的；TJH 上 52.70%。OpenBioLLM-8B 再入院 50.21%、TJH 56.75%。Gemma-3-4B、Qwen2.5-7B 也都在及格线附近晃。所谓"医疗微调小模型"（OpenBioLLM、HuatuoGPT-o1）在这个任务上**没有体现出任何领域优势**。
**多智能体的"提升"来自哪里？**这是本节最关键的一笔。ColaCare 在 MIMIC-IV 死亡上 82.91%，确实明显高于它自己的底座 DeepSeek-V3 的 76.86%；MedAgents 81.53%、ReConcile 77.81% 也都有提升。但它们**统统打不过 GPT-4o 这个单模型**。论文对此的判断非常直白：这些温和的提升很大程度上是**底座模型的功劳，而不是多智能体策略带来的变革性优势**；QA 式的协作框架对结构化数据预测可能压根就不对路。
附录里还藏了一个反直觉结果（不同提示策略对比）：DeepSeek-R1 在 MIMIC-IV 死亡上从 Basic 的 73.68% 涨到 Opt.+ICL 的 83.95%（加单位、参考范围和示例很有用），但在 TJH 上反而从 90.63% 掉到 85.59%。**提示工程在 EHR 上的收益不稳定，甚至可能是负的**——这个观察比主表更值得后续研究跟进。
锐评：如果只让我留这篇论文的一张表，我留这一张。它把一件业内心知肚明但很少写进论文的事钉在了纸面上：**在结构化 EHR 预测上，一个 2020 年的 AdaCare 打十个 2025 年的 LLM agent**。想在这个方向做出真东西的人，第一件事应该是想清楚"我为什么不直接用 GRU"。

## 4：任务四：工作流自动化，多智能体唯一的主场

这一节多智能体终于赢了，但赢的方式值得细看。
**优势体现在"把活干完"，不是"干得更聪明"**。核心对比是"No Result"这一行：TJH 建模任务上，单 LLM 有 **50.00% 直接没结果**、31.83% 是"模型没保存"，最终只有 8.42% 正确；OpenManus 无结果率只有 4.17%，正确率 **64.0%**。MIMIC-IV 建模任务上单 LLM 正确率 9.08%（"模型未保存"高达 57.46%），SmolAgents 47.62%、OpenManus 39.84%。报告生成更明显：MIMIC-IV 上单 LLM **55.23% 干脆没生成报告**，OpenManus 只有 15.38%，清晰呈现率 34.46% 对单 LLM 的 5.15%。
原因不神秘：这些框架**自带 Python 执行等工具能力**，能真的把代码跑起来、把文件存下来。单 LLM 只是生成一段代码文本，容易在多步之间丢上下文、搞错顺序、忘记落盘。所以这里的胜负，本质上是"**有工具 + 有状态管理**"对"**只会生成文本**"的胜负，不是"多个脑袋"对"一个脑袋"的胜负。
**但整体正确率依然很低**。除了数据抽取这一档（SmolAgents 在 MIMIC-IV 上 90.25% 正确，是全表最亮的数字），后面越走越崩：可视化正确率 MIMIC-IV 上最高只有 SmolAgents 的 29.25%（单 LLM 18.09%，Owl 12.5%），建模和报告普遍在 40–50% 以下。**流水线越往后，成功率衰减越厉害**——这是 long-horizon 任务的典型失效模式。
**框架之间差异巨大，选错框架比不用还糟**。Owl 在 MIMIC-IV 建模任务上正确率 **0.00%**、无结果率 76.92%；可视化上 58.33% 完全没画图。OpenManus 和 SmolAgents 明显优于 Owl。这意味着"多智能体"根本不是一个可以整体评价的类别，工程实现质量的方差比范式差异还大。
可靠性方面，Fleiss' Kappa 为 Data 0.61、Modeling 0.56、Visualization 0.54、Reporting 0.40。前三项算中等到较好，**Reporting 只有 0.40，属于一般水平**——也就是说"报告写得好不好"这件事连六位专家之间都难以达成一致，那一行数字应该打折看。
锐评：这一节是全文最有前瞻性的部分，也最接近真实的临床科研场景。但作者没有把最关键的消融做掉：**给单 LLM 也配上代码执行工具**。现在的对照是"裸单 LLM"对"带工具的 agent 框架"，赢的到底是协作还是工具，这张表没法区分。而从"No Result"和"Model Not Saved"这两行数字的形态看，我押注绝大部分增益来自工具和状态管理。

## 5：成本账，以及一个反直觉的发现

v2 补了一节成本分析（附录 D），按 DeepSeek API 定价算，两个指标：平均讨论轮数和测试集总花费。

- 讨论轮数上，**ReConcile 最烧**，PubMedQA 自由生成要 2.30 轮——因为它刻意给每个 agent 用不同底座，意见分歧大，收敛慢。**MDAgents 最省**，VQA-RAD 选择题上低到 0.035 轮，因为它有难度门控（difficulty gating），简单题直接单 agent 上，讨论轮数记零，把均值拉了下来。
- 花费上，多智能体普遍比 zero-shot / CoT 贵：ReConcile 在 PubMedQA 自由生成上 $9.32，而 zero-shot 在 MedQA 上只要 $0.39。
- **反直觉的地方**：文本 QA 任务上**最贵的方法根本不是多智能体，而是单 LLM 的 CoT-SC**——MedQA $7.99、PubMedQA 选择题 $10.52、自由生成 $13.50，把最能开会的 ReConcile 都超了。原因是它要生成多份 token 密集的思维链再投票。
  锐评：这一节是全文最容易被忽略但对实践最有用的。它顺手拆掉了一个常见的偷懒论证——"多智能体太贵所以不值得"。真相是**复杂的单模型推理策略同样烧钱**，性价比这件事必须每个方法单独算，不能按范式贴标签。同时也说明 MedQA 上 CoT-SC 那个 89.90% 的第一名，是用全场最高的成本换来的。

## 6：作者自己划定的边界

论文的 Limitations 写得比多数 benchmark 诚实，三条：

1. **所有 LLM 方法的表现都绑在底座能力上**，所以这里的排名会随着更强模型出现而改变——结论是"某一时刻的快照"。
2. **四类任务不穷尽真实临床的复杂度**；尤其工作流自动化只有 100 道人工筛选的题，覆盖不了真实场景的动态性。
3. **指标可以更深**，需要引入更多定性人评来衡量临床效用、可信度，以及协作动力学的微妙之处。
   Future work 指了三个方向，其中一条格外值得注意：**探索混合架构——让传统模型负责特征提取，让 LLM agent 负责复杂推理**，特别是在 EHR 预测上。另外两条是跨模态的多智能体策略（别再只靠文字交换），以及鲁棒性、可解释性、公平性、隐私。
   Broader impact 里还有一句难得的自我提醒：过度引用本文结论可能被误读成"对多智能体的全面否定"，从而抑制创新。锐评：这句话说得对，但也说明作者清楚自己写出了一篇容易被当作弹药引用的论文。而以我的经验，这类"扫兴型" benchmark 的结论在传播中一定会被简化成一句口号，作者的免责声明基本不会被一起转发。

# Step 3：other

## 1：重点

最值钱的不是"多智能体不行"这个结论——这个结论在通用领域已经被 MAST 等工作说过了。真正值钱的是三样东西。
**第一，两个机制性解释，这是全文最可复用的思想。**（a）**任务可分解性（task decomposability）**：多智能体只在复杂任务能被拆成契合角色分工的逻辑子步骤时才有效——工作流自动化里"读数据 → 跑模型 → 画图"天然可拆，所以赢；（b）**信息保真瓶颈（information fidelity bottleneck）**：在感知受限的任务（如 VQA）里，第一步视觉环节丢掉的关键细节，后续无论开多少轮纯文本讨论都无法恢复，所以多个 agent 反而互相放大同一个错误。这两条给了"什么时候该上多智能体"一个可操作的判据，比任何一张表格都更有指导价值。
**第二，传统方法必须回到基线表。** 在结构化 EHR 预测上，AdaCare 的 AUROC 94.28% 对 GPT-4o 的 85.99%，AUPRC 81.93% 对 42.20%——AUPRC 上的近一倍差距说明 LLM 在不平衡正类排序上还远不能用。任何一篇不跟 GRU/XGBoost/AdaCare 比就宣称 LLM agent 在 EHR 预测上有效的论文，都应该被要求补这一栏。
**第三，多智能体的"提升"要跟底座解耦。** ColaCare（82.91%）>  它的底座 DeepSeek-V3（76.86%），但 < GPT-4o（85.99%）。这个三段式对比是全文最锐利的一刀：**你以为的协作收益，可能只是换了个更强的模型。** 与之配套的是成本发现——CoT-SC 比多智能体更贵（$13.50 对 $9.32），说明"复杂 vs 简单"的成本直觉也是错的。
以及一个附带的实践结论：工作流自动化上的增益主要来自**工具调用 + 状态持久化**，而不是"多个脑袋一起想"。这对做 agent 的人是个明确的资源分配信号——把预算花在工具、执行环境和状态管理上，回报大概率高于把预算花在设计更花哨的角色扮演协议上。

## 2：意见

**最致命的问题：底座不对等，导致核心结论无法成立。** 所有多智能体框架的底座统一是 DeepSeek-V3-0324，而单 LLM 赛道里却放进了 GPT-4o、DeepSeek-R1 这些更强的模型。于是"多智能体打不过最好的单 LLM"这个结论，完全可以被一个远更平凡的解释吃掉——**DeepSeek-V3 打不过 GPT-4o**，跟"协作机制无效"根本没有关系。看 EHR 那一列就很清楚：ColaCare(V3) 82.91% < GPT-4o 85.99%，但 ColaCare(V3) > DeepSeek-V3 76.86%。也就是说，在**同底座**的唯一一组合法对照里，多智能体其实是赢的，涨了 6 个点。论文在 4.3 节自己写下了"提升很大程度上由底座驱动"这句判断，却恰恰没有做那个能验证这句话的实验：**把 GPT-4o 作为底座跑 MedAgents / ColaCare / ReConcile，再跟 GPT-4o 单模型比**。这个消融的成本远低于论文已经做过的工作量（附录显示 MedQA 全量多智能体实验只要几美元），却是整篇论文结论成立的唯一支点。
这对 benchmark 类论文是致命的，原因在于影响力的不对称：benchmark 的结论会被大量引用当作既定事实，而"多智能体在医疗上不如单 LLM"这句话一旦流传出去，几乎没人会回头检查它是在什么底座配置下得出的。同样的不对等在别处也反复出现——工作流自动化里是"带工具的 agent 框架"对"裸单 LLM"，通俗摘要里是"ROUGE 优化过的微调模型"对"没见过参考风格的 LLM"。每一处都存在一个比"多智能体无效"更简单的替代解释，而论文没有一处把它排除掉。**修改建议很具体：把所有跨范式对比锁定同一底座、同一工具权限，再报结论；否则请把标题和摘要里的因果性措辞降级为相关性描述。**

## 3：相关工作

**MedAgentsBench（arXiv:2503.07459，2025）**：Tang 等人（MedAgents 原作者团队）做的医学推理 benchmark，专门针对**复杂**医学推理任务评测 thinking model 和 agent 框架，结论是最新的推理型模型在复杂医学推理上表现突出。跟 MedAgentBoard 是一对镜像：它把 QA 挖得更深（筛出真正难的题），MedAgentBoard 把任务铺得更宽（跨四类任务三种模态）。两篇一起读能看清"多智能体在医学 QA 上到底有没有用"这个问题的两个切面——如果你只关心推理难度，前者更相关。

**《Why Do Multi-Agent LLM Systems Fail?》/ MAST（arXiv:2503.13657，2025）**：Cemri 等人（Berkeley）在编程、跨应用网页任务、数学推理、知识 QA 上系统研究多智能体失败模式，提出 **MAST 失败分类法**，结论跟 MedAgentBoard 高度一致：多智能体并不能稳定超过一个 well-prompted 的单 LLM 基线。它是 MedAgentBoard 在通用域的前身和思想来源。价值在于它不止说"不行"，还把"为什么不行"拆成了可诊断的类别（规范违背、协作失调、任务验证缺失等），对调试自己的 agent 系统比看 benchmark 分数有用得多。

**ColaCare（WWW 2025）**：Wang 等人的工作，用 LLM 驱动的多智能体模拟多学科会诊（MDT）来做 EHR 建模，思路是把传统 EHR 模型当作"专科医生"接入讨论，再由 LLM agent 整合。有意思的是它既是 MedAgentBoard 的**被测对象**，又跟 MedAgentBoard 出自同一课题组——某种程度上作者在拿自己的方法开刀。但它也正好指向 MedAgentBoard 在 Future Work 里推荐的方向：**混合架构**（传统模型做特征提取和表征、LLM agent 做推理和解释）。同组还有一篇 **ClinicRealm（arXiv:2407.18525）**，是本文在 EHR 预测上"重新评估 LLM vs 传统 ML"这条主线的直接前作，做 EHR agent 方向的话建议连着一起看。

# 复现
查了论文和代码仓库，给你一个分难度的判断。

## 先定性：这是 benchmark 论文，不是方法论文
MedAgentBoard（NeurIPS 2025 D&B Track，港大+北大 Lequan Yu / Liantao Ma 组）的核心结论是"多智能体协作并不总是更好"——在医学 VQA 和 EHR 预测任务上，专门的传统方法通常表现更好；在文本医学 QA 上，先进的单个 LLM 就够了；多智能体只在临床工作流自动化这类任务上体现出完整性优势。
所以"复现"它 ≠ 训练一个模型，而是**重跑一整套评测流水线**。难度不在算法，在工程 + 数据授权 + API 预算。

## 四个任务分开看，难度差异极大

**Task 1 医学（视觉）问答 — ⭐⭐ 容易**
数据集都是公开的（PubMedQA、MedQA、VQA-RAD 等），代码就是 `medagentboard/medqa/` 下几个脚本，复现了 ColaCare、MDAgents、MedAgents、ReConcile 等框架。仓库用 uv 管理依赖，`uv sync` 装好，配 `.env` 里的 API key（DeepSeek / DashScope / ARK 等）就能跑。真正的成本是 API 调用费。

**Task 2 通俗摘要生成 — ⭐⭐ 容易**
数据集公开（Cochrane/PLOS 系列），`laysummary/` 目录有 AgentSimp 多智能体实现和单 LLM baseline。唯一坑是评测用了 LLM-as-judge（`utils/llm_scoring.py`），judge 模型换了分数就会漂。

**Task 3 结构化 EHR 预测 — ⭐⭐⭐ 中等，卡在数据授权**
这是跟你方向最相关的一块。数据是 MIMIC-IV + TJH（清华同济新冠数据集，公开可下）。作者明确说明 MIMIC 相关的数据和结果没有放进开源包，因为需要 PhysioNet 授权。
→ **这一步的时间成本主要不是写代码，是等审批**：PhysioNet credentialed access 要做 CITI "Data or Specimens Only Research" 培训、签 DUA、找导师做 referee，通常 1–4 周。**建议你现在就去申请**，不管最后复不复现都用得上。
TJH 数据集小（几百人），可以先拿它把 pipeline 跑通。

**Task 4 临床工作流自动化 — ⭐⭐⭐⭐⭐ 最难，本质上无法完全复现**
两个硬伤：
1. 要分别 clone 并配好 OpenManus、Owl、SmolAgents 三个框架的环境——这三个 agent 框架依赖重、版本漂移快，2025 年 5 月的代码到现在大概率已经装不动了，需要自己 pin 版本或改代码。这些框架会生成并执行代码，还得配沙箱。
2. 评测是 3 位标注者（A/B/C）的人工评估 + 合并共识。你一个人做不了这个，最多用 LLM-as-judge 近似替代，那就不算严格复现了。

## 综合结论

| 复现范围 | 难度 | 时间估计 |
|---|---|---|
| Task 1+2（纯文本/图像 QA + 摘要） | ⭐⭐ | 3–5 天 |
| + Task 3 EHR（TJH 部分） | ⭐⭐⭐ | 再加 3–5 天 |
| + Task 3 MIMIC 部分 | ⭐⭐⭐ | 卡在 1–4 周授权等待 |
| + Task 4 全套 | ⭐⭐⭐⭐⭐ | 1–2 个月且结果无法对齐 |

**几个必须提前知道的坑：**
- **API 费用是真实开销**。论文跑了多个模型 × 多个框架 × 多个数据集，多智能体一个 case 就要十几到几十次调用。全量复现估计几百到上千元人民币。建议先用 DeepSeek/Qwen 这类便宜模型 + 小样本切片跑通。
- **数字对不上是正常的**。LLM 有随机性，且论文用的模型版本（DeepSeek-V3、Qwen-Max 等）现在的 checkpoint 已经变了。你能复现的是**趋势和排序**，不是小数点。
- 仓库文档偏薄，README 里出现"may need specific setup"这种措辞，说明作者自己也知道不是开箱即用。但作者留了邮箱且 Issue 区活跃度不低（52 star / 2 issues），可以直接问。

## 锐评 + 给你的建议
说句实在的：**你可能不该"复现"这篇论文，而该"用"它**。

它是个 benchmark，复现出来你只是重新验证了"多智能体没那么神"这个结论——发不了论文，也不构成你 EHR agent 的技术积累。对你更有价值的做法是：
1. **只跑 `medagentboard/ehr/` 这一个模块**，把它当成你自己 EHR agent 的**对照基线**。你未来做的 agent 直接在这套评测框架上比，省掉自己搭 baseline 的巨大工作量。
2. **把 MedAgentBoard 当作"负面结果地图"**——它告诉你多智能体在 EHR 预测上打不过传统方法（GRU/Transformer/XGBoost）。这恰恰是你的机会：你的 agent 要么在它证明"多智能体有用"的方向（workflow automation）发力，要么想办法解决它指出的失败原因。
3. 顺带一提，**同一作者组（yhzhu99）后续做了 HealthFlow**——一个自演化多智能体框架，专门做 EHR 分析自动化，而且直接把 MedAgentBoard 当 benchmark 用。这基本就是"从这篇论文往下走一步"的标准答案，值得你先去看看，避免撞车或者可以站在它肩上。
