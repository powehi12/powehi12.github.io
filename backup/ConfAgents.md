# 前言

标题：ConfAgents: A Conformal-Guided Multi-Agent Framework for Cost-Efficient Medical Diagnosis（Zhao et al., 2025）
论文链接：https://arxiv.org/abs/2508.04915
代码链接：https://github.com/PKU-AICare/ConfAgents
作者单位：北京大学 / 香港大学 / 爱丁堡大学 / HDR UK（与 ColaCare 是同一个组，Liantao Ma 通讯）

标签：医疗多智能体；保形预测；自适应推理成本；迭代式 RAG

摘要：一句话概括，这篇论文干的事就是给多智能体医疗问诊系统装了一个"分诊台"——简单的题目让一个大模型直接答完就走，只有它自己拿不准的难题才叫上一堆专家 agent 开会查资料，从而在几乎不掉准确率的前提下把耗时砍掉一大半。核心内容有三块：用**保形预测（Conformal Prediction）**构造一个 CP Judger，把主 agent 输出的选项概率转成一个"预测集合"，集合里只剩一个选项就说明有把握、直接输出，剩下多个选项就说明没把握、触发会诊；对被升级的难题，动态招募对应科室的 AssistAgent，每个 agent 把问题拆成子问题、检索医学指南、合成证据报告，并迭代多轮直到判断明确；最后由 MainAgent 综合所有证据报告给出终审答案。实验在 MedQA、MMLU、MedBullets、AfriMedQA 四个医学选择题基准上完成，ConfAgents 在准确率上追平或超过现有多智能体框架，同时在 MedQA 上比最快的多智能体基线还快 2.76 倍、比最慢的快 7.71 倍。

# Step 1：论文解读

## 1：这篇论文想解决什么问题

先说清楚这篇文章的"敌人"是谁。过去两年医疗 AI 圈流行一种玩法：让好几个大模型分别扮演不同科室的医生，围坐一桌辩论、投票、达成共识，以此提高诊断准确率。代表作有 MedAgents（投票）、ReConcile（按置信度加权投票）、MDAgents，以及这个组自己上一篇 ColaCare。效果确实有提升。
但作者拍了一张很扎心的表（论文 Table 1，MedQA + GPT-4o）：

| 方法                      | 单次耗时 | 准确率 |
| ------------------------- | -------- | ------ |
| Zero-Shot（单模型直接答） | 2.1s     | 48.6%  |
| Self-Consistency          | 10.6s    | 51.2%  |
| MedAgents（多智能体）     | 113.4s   | 58.8%  |
| ColaCare（多智能体）      | 98.3s    | 60.8%  |

**多智能体比单次调用慢了将近 50 倍，换来 12 个百分点。** 这笔账在论文里划得来，在医院里划不来——一个门诊医生不会为了一道简单题等 100 秒。
更关键的观察是：**这 12 个点的收益，其实集中在一小撮真正的难题上。** 绝大多数医学问题，单个模型就能高置信度、高准确率地答对，把它们也拉去开一场三轮辩论，纯属浪费。作者把这个毛病叫做"one-size-fits-all"（一刀切）。
所以自然的思路就是：**分诊**。像急诊科一样，简单的直接处理，疑难的才请专家会诊。但要落地，有两个坎：

1. **怎么判断"这道题我拿不准"？** 直接问大模型"你有多大把握"是不行的——LLM 出了名的校准差（miscalibrated），经常一边胡说八道一边信誓旦旦。
2. **难题叫来一堆 agent 就够了吗？** 不够，如果这些 agent 全靠预训练里的静态知识，遇到冷门或最新的问题照样集体犯错，它们需要能意识到"我不知道"并主动去查资料。

ConfAgents 就是分别用 **CP Judger** 和 **迭代式 RAG** 来解这两个坎。

## 2：核心思路——给多智能体系统装一个"分诊台"

整个流程是**四阶段、但可能只走一步**：

1. MainAgent（主诊医生）先自己看一遍题，输出对每个选项的概率分布；
2. CP Judger 拿这个概率分布构造一个"预测集合"，判断要不要升级；
3. 集合大小 = 1 → 直接采纳 MainAgent 的答案，**流程结束**（这就是省钱的来源）；集合大小 ≥ 2 → 触发会诊，动态招募 AssistAgents 做迭代 RAG 取证；
4. MainAgent 拿到所有证据报告，重新综合，出终审答案。

**锐评**：这个骨架本身其实很朴素，就是"自适应推理算力分配"——难题多花算力、简单题少花算力。这个思想在推理模型（长思维链 vs 短思维链）、MoE 路由、cascade 推理里都出现过。这篇论文的真正贡献不在于"要分诊"这个想法（MDAgents 早就在做类似的事），而在于**用什么信号来分诊**。下面这一节才是全文的核心。

## 3：CP Judger——用保形预测判断"要不要会诊"

### 3.1：保形预测三分钟入门

保形预测（Conformal Prediction, CP）是一套统计框架，它不给你"最可能的那个答案"，而是给你**一个候选答案的集合**，并承诺："真实答案落在这个集合里的概率不低于 1−α"。α 是你自己定的容错率，比如 α=0.1 就是 90% 覆盖率。
它最大的卖点是 **distribution-free**：不需要假设数据服从什么分布，也不管底下的模型是什么，只要满足一个条件（校准集和测试样本"可交换"，exchangeability），这个覆盖率保证就在**有限样本**下严格成立。这个"记住它"很重要，后面的意见部分全靠它。
具体怎么做（split CP，划分式保形预测）：

- 定义一个**不符合度分数** g(x, y)，衡量候选答案 y 对输入 x 有多"不合群"。分类任务的标准选法就是 g(x,y) = 1 − p(y|x)，即"1 减去这个选项的概率"，概率越低越不合群。
- 准备一个**校准集** D_cal（有标准答案的历史样本），算出每个样本**正确答案**的不符合度分数，得到一堆分数。
- 取这堆分数的 (1−α) 分位数作为阈值 τ（带有限样本修正：τ = Quantile(S_cal, ⌈(n+1)(1−α)⌉/n)）。
- 对新样本，把所有分数 ≤ τ 的选项都塞进预测集合。

**集合的大小就是不确定性的直观度量**：只剩一个选项 = 很有把握；剩三四个 = 心里没底。

### 3.2：ConfAgents 具体怎么用它

MainAgent 先输出各选项概率 p（白盒模型直接取 logits，黑盒模型靠采样或让模型自报），初诊答案就是概率最大的那个。然后：

- 不符合度分数 g(x,y) = 1 − p(y|x)；
- **校准集不是固定的**，而是**为每个测试样本临时构造**：从知识库里挑出 N 道语义上最相似的题目当校准集；
- 算出 τ，构造预测集合 C(x_test)；
- |C| = 1 → 高置信，直接输出，收工；|C| > 1 → 低置信，触发会诊。

**锐评**：把"要不要升级"这件事从"概率 > 0.8 就算有把握"这种拍脑袋阈值，换成一个有统计学定义的预测集合大小，方向是对的，而且比 MDAgents 那种"让 LLM 自己判断题目难不难"要靠谱得多——毕竟裁判不能是被审的那个人。但**"为每个测试样本挑最相似的题目当校准集"这一步，恰恰把保形预测赖以成立的前提给破坏了**，这是全文最大的问题，我放到意见部分说透。另外还有个细节割裂：正文说黑盒模型可以"近似"概率，但附录 D.1 的 prompt 是直接让模型输出 `conf_each_option` 这个自报置信度字典——而这篇论文的立论前提，正是"LLM 自报置信度不可信"。用不可信的分数去做严格的统计推断，严格性只存在于阈值那一环。

## 4：升级后的会诊——动态选专家 + 迭代式 RAG

被判定为难题之后，系统做两件事。
**第一，动态招募专家。** MainAgent 看一眼预测集合里剩下哪几个候选选项，判断它们涉及哪些科室（心内科、神经科……），然后每个科室招一个 AssistAgent。注意这里的巧妙之处：**招谁不是预先写死的，而是由不确定性集合的内容决定的**——模型在哪几个诊断之间摇摆，就叫哪几个方向的专家来。
**第二，每个 AssistAgent 跑一个迭代 RAG 循环：**

1. **问题拆解**：把"这道题该选哪个"拆成几个精确的子问题（prompt 里明确要求写成适合 embedding/BM25 检索的搜索引擎式查询，这个细节很实用）；
2. **证据检索**：每个子问题去医学语料库（还是《默沙东诊疗手册》MSD）里召回 top-k 篇文档，k=3；
3. **报告合成**：过滤、抽取、综合成一份连贯的证据报告；
4. **迭代精炼**：基于报告重新下判断，如果判断变得明确就退出，否则改写子问题再来一轮，最多 3 轮。

**锐评**：这里最值得抄的是 **"让 agent 自己意识到知识缺口，再去检索"** 这个循环，而不是传统 RAG 那种"一次性检索、爱用不用"。prompt 里还专门写了一句"检索到的内容可能不相关或有错误，你必须批判性地评估其可靠性"——这是被 RAG 噪声坑过的人才会写的话。但另一方面，"迭代直到判断明确"这个终止条件是有隐患的：**模型越迭代越自信，不代表越迭代越正确**，这个循环没有任何机制防止它自我强化一个错误结论。

## 5：最后一步——MainAgent 综合裁决

所有 AssistAgent 的报告汇总给 MainAgent，它结合自己的初诊意见和这些证据，输出终审答案。论文特意强调：**不是简单数票**（这是在点 MedAgents 的投票机制），而是"整体性地综合各方论证与发现"。
所以 ConfAgents 里其实**没有真正的辩论**——AssistAgents 之间互相看不见对方的报告，各自独立取证，最后由 MainAgent 一个人融合。作者在局限性里也大方承认了这一点：缺少 agent 之间直接的质疑与论辩机制。

## 6：和 ColaCare 对照着看

这两篇是同一个组的连续作，放在一起看很有意思：

- **ColaCare** 处理的是**结构化 EHR 数值表格**，靠的是"专家模型算数 + LLM 说人话"，目标是**准**和**可解释**；
- **ConfAgents** 处理的是**文本选择题（medical QA）**，靠的是"保形预测分诊 + 迭代 RAG"，目标是**快**和**省**。

而且 ConfAgents 直接把 ColaCare 当成基线打。这里有个必须说的实验细节：为了让 ColaCare 能跑选择题任务，作者**把它的输入从结构化 EHR 数据改成了文本描述**。可是 ColaCare 的整个性能来源就是背后那三个训练好的专家模型（它自己的消融显示，去掉专家模型 AUPRC 从 54 掉到 27.7）。**被剥掉专家模型的 ColaCare，本质上就退化成了一个 MedAgents 变体**，拿它当"最强多智能体基线"来比，这个比较是不太公平的——虽然公平的方向是对基线不利还是有利，得看具体数字（表 2 里 ColaCare 其实还挺能打）。

# Step 2：实验部分

## 1：实验怎么设置的

数据集四个，全是**医学选择题**：MedQA（中美执业医师考试题）、MMLU 的医学子任务、MedBullets（USMLE 题库）、AfriMedQA（南非执业考试，非洲医疗语境）。每个数据集按 MedAgentsBench 的采样策略切出 Test-Hard 和 Test-Normal 两个子集，**各 100 个样本**。
指标四个：ACC（准确率）、P-Time（端到端延迟，秒/题）、C-Tokens（生成 token 数）、T-Tokens（总 token 数），外加一个自定义的 BES（下面讲）。结果用 bootstrap 100 次报告 mean±std。
基线：单智能体的 zero-shot / few-shot / self-consistency，多智能体的 MedAgents、ReConcile、MDAgents、ColaCare。所有基线统一用 DeepSeek-V3 作为底座、3 个 agent、3 轮迭代。
超参：α = 0.05，检索 k = 3，最大 RAG 轮数 3。硬件依然是**单张 RTX 3090**（其实只是跑检索和编码，LLM 全走 API）。

## 2：主实验——准确率和延迟能不能双赢

GPT-4o 底座下的 MedQA 结果最有代表性：

| 方法           | ACC (%)   | 耗时 (s) |
| -------------- | --------- | -------- |
| Zero-Shot      | 56.80     | 1.17     |
| Few-Shot       | 72.40     | 1.15     |
| MedAgents      | 78.80     | 70.21    |
| ColaCare       | 79.90     | 56.74    |
| MDAgents       | 75.10     | 25.15    |
| ReConcile      | 78.10     | 46.09    |
| **ConfAgents** | **80.21** | **9.11** |

这一格是全文最漂亮的结果：**准确率最高，耗时只有次快基线（MDAgents）的三分之一、最慢基线的二十分之一。** 在 DeepSeek-V3 底座下 MedQA 也是最高（75.70），AfriMedQA 上更是大幅领先（69.50 vs 次高 61.10）。
但要泼两盆冷水：
**第一，不是全赢。** DeepSeek-V3 底座下，MMLU 上 MedAgents（84.40）明显高于 ConfAgents（80.00）；MedBullets 上 GPT-4o 底座的 MedAgents（72.10）也高于 ConfAgents（70.81）。作者的措辞是"superior **or competitive**"，这个"or competitive"是有分量的。
**第二，Table 1 和 Table 2 的数字对不上。** 引言里那张 Table 1 说 MedQA + GPT-4o 下 zero-shot 是 48.6%、ColaCare 是 60.8%、MedAgents 耗时 113.4s；到了 Table 2，同样是 MedQA + GPT-4o，zero-shot 变成 56.80%、ColaCare 变成 79.90%、MedAgents 耗时变成 70.21s。差了 20 个百分点。论文没有解释这两张表用的是不是不同子集（大概率一张是 Hard、一张是混合，但没写）。**引言里用来立论的那张表，如果口径和主实验不一致，立论的说服力是打折的。**

## 3：成本分析与 BES 指标

MedQA + GPT-4o 的绝对成本（论文 Table 3）：ConfAgents 耗时 9.11s、生成 token 0.33×10⁵、总 token 2.10×10⁵；对比最省的基线 MDAgents（25.15s / 0.66×10⁵ / 2.56×10⁵），分别快 2.76 倍、少 2.01 倍、少 1.22 倍。
注意**总 token 只省了 1.22 倍，但生成 token 省了 2.01 倍**。这个差值很说明问题：ConfAgents 省的主要是"输出"（不用长篇大论辩论），输入侧因为要做 RAG 检索、塞文档，反而没省多少。而在真实 API 计费里，输出 token 通常比输入贵好几倍，所以这个省法在钱上是划算的，在上下文长度上则未必。
作者还自造了一个指标 **BES（Balanced Efficiency Score）= 归一化准确率 − 归一化耗时**，范围 −1 到 +1，越高越好。ConfAgents 在四个数据集上拿到 0.61 / 0.36 / 0.47 / 0.61，基本都是最好或接近最好；ReConcile 则是灾难性的 −0.72 / −1.00 / −0.22 / −1.00。
**锐评**：BES 这个指标要小心看。它是**在当前这批方法内部做 min-max 归一化**之后再相减的，所以数值完全取决于你把哪些方法放进这张表——加一个更慢的方法进来，所有人的 Timenorm 都会变，排名可能翻转。而且"准确率 1 个点"和"耗时 1 秒"被隐式赋予了相同权重，这在临床上显然不成立。它是个方便的可视化，不是一个可以横向引用的指标。

## 4：消融实验——最有意思的一行是"w/o Adaptive"

MedQA + DeepSeek-V3：

| 变体                                | ACC (%)   | 耗时 (s) | 生成 token |
| ----------------------------------- | --------- | -------- | ---------- |
| w/o 迭代 RAG（改成单轮检索）        | 65.50     | 10.78    | 11,093     |
| w/o CP Judger（改成朴素置信度阈值） | 67.80     | 109.87   | 153,545    |
| w/o Adaptive（所有题目都开会诊）    | **76.50** | 193.29   | 277,204    |
| ConfAgents                          | 75.70     | 65.72    | 97,268     |

三个结论，一个比一个重要：
**第一，迭代 RAG 是准确率的主要来源。** 换成单轮检索直接掉 10 个点（75.70 → 65.50），掉得比去掉 CP Judger 还多。也就是说，这篇论文标题里挂着的"Conformal-Guided"其实主要贡献**效率**，贡献**准确率**的是那个不那么起眼的迭代 RAG 模块。
**第二，CP Judger 的价值是"别乱升级"。** 换成朴素置信度阈值后，准确率掉 8 个点，耗时反而暴涨到 109.87s——说明朴素阈值把大量本该直接放行的简单题也误判成难题送去会诊了，既慢又没变准。这个对比确实证明了 CP 判据比拍脑袋阈值好。
**第三，也是最要命的一行——去掉自适应机制（所有题都会诊），准确率反而更高（76.50 > 75.70）。**
**锐评**：这一行等于承认了：**ConfAgents 不是"更准"，而是"用 0.8 个点的准确率换 3 倍的速度"。** 这本身是一个完全正当、甚至很诚实的 Pareto 权衡，我很欣赏作者把这行数据放出来。但它和摘要里"achieves state-of-the-art accuracy"的表述是有张力的——严格讲，SOTA 准确率属于它自己的 w/o Adaptive 变体，而不是属于 ConfAgents。在医疗场景里，0.8 个点的准确率损失是否可以接受，是一个需要论证的临床问题，而不是一句"trade-off 很划算"能带过的。

## 5：敏感性分析与人工评测

**换底座**：DeepSeek-chat 73.00%、GPT-4o 77.00%、GPT-4o-mini 55.00%、Kimi-K2 66.00%（MedQA）。有个反直觉的现象：更强的 GPT-4o 不仅更准，**还比更小的 GPT-4o-mini 更快**（9.11s vs 19.01s）。原因很清楚——强模型的预测集合更容易收缩成单元素，触发会诊的比例低，所以整体反而更快。这个观察挺有价值：**在自适应框架下，用更强的模型可能是更省的**。
不过这张表和主表又对不上：Table 6 里 GPT-4o 的 MedQA 是 77.00，Table 2 里 ConfAgents + GPT-4o 是 80.21；DeepSeek 是 73.00 对 75.70。论文没解释差异来源（大概率一个是单次跑、一个是 bootstrap 均值，或者子集不同），但一篇文章里同一个配置出现两套数字，是审稿人一定会圈出来的。
**调 α**：α 从 0.005 到 0.2，准确率缓慢下降、耗时显著下降。这符合直觉——α 越小系统越谨慎、越爱开会诊。作者选 α=0.05 作为平衡点。这是个很好的性质：**α 是一个可解释的、单调的旋钮**，医院可以按科室风险等级自己调，急诊调小、常规咨询调大。
**人工评测**：找了 14 位专家（AI for healthcare、生信、临床医学、生物医学工程方向的 MD 或 PhD 学生），对 ConfAgents / ColaCare / MedAgents / MDAgents 四种方法的回答做匿名随机排序的盲评，题目是 16 道（MedQA 8 + MedBullets 8）。结果 ConfAgents 平均偏好率 **95.54%**，中位数 100%，14 人里有 9 人在全部 16 题上都选它，偏好最低的专家也选了 68.75%。
**锐评**：95.54% 这个数字高得有点不真实。**16 道题、4 个方法**的样本量，是撑不起"压倒性偏好"这种结论的。而且评委是"AI for healthcare / 生信 / 生物医学工程方向的博士生"，只有一部分是临床医学背景——他们评的很可能是**回答读起来有多结构化、有多像模像样**，而不是临床上有多正确。ConfAgents 的输出因为带 RAG 证据和结构化推理步骤，天然在"看起来专业"这一维度占优。这个实验证明的是"输出可读性好"，不是"临床价值高"，论文的措辞（"significantly more coherent, trustworthy, and clinically valuable"）是超出证据范围的。

# Step 3：other

## 1：重点

**第一，也是最值得带走的：多智能体协作的收益是高度不均匀的，绝大多数样本根本不需要它。** 论文用 Table 1 和消融把这件事量化了——多智能体比单次调用慢约 50 倍，而"全量会诊"相对"自适应会诊"只多了 0.8 个准确率点。任何做 agent 系统的人都应该把这条钉在墙上：**先问"这个 case 值不值得多花算力"，再问"怎么协作更好"**。这本质上是把推理模型里的"自适应思考长度"搬到了多智能体系统上，思路可以迁移到任何 agent 框架。

**第二，用预测集合的大小、而不是概率阈值，作为升级信号。** 概率阈值（">0.8 就算有把握"）是绝对量，跨题目、跨数据集、跨模型都不可比；预测集合大小是相对量，阈值 τ 由校准集自适应决定，天然做了归一化，还自带一个可解释的旋钮 α。这个设计的**工程价值**是实打实的，哪怕它的**理论保证**（见下）站不住。

**第三，让 agent 在推理中途自己发现知识缺口、拆子问题、再检索的迭代式 RAG，才是准确率的真正来源。** 消融显示它值 10 个点，比 CP Judger 还多。这也提醒一件事：**很多多智能体论文里所谓"协作的收益"，可能大部分其实是"多检索了几轮"的收益**——如果不做这个消融，就会把功劳记错地方。

**第四，一个很自然的落地形态**：CP Judger 天然就是一个 human-in-the-loop 的挂载点。作者自己在 future work 里也提到了——把预测集合大的病例直接转给真人医生，而不是转给另一群 LLM。这可能比论文正文写的东西更有实用价值。

## 2：意见

**这篇论文的核心卖点是"rigorous statistical guarantee"，但它自己的实现让这个保证失效了，而且它承诺过的验证从未出现。**
保形预测的有限样本覆盖率保证，唯一的前提是校准集与测试样本**可交换（exchangeable）**。而论文 3.2 节明确写道：校准集不是固定的全局集合，而是**针对每个测试样本，从知识库里挑出语义上最相似的 N 道题**。这是一个**用测试点本身去选择校准数据**的操作，直接破坏了可交换性——挑出来的"相似题"分布已经被测试样本条件化了，此时 τ 的 (1−α) 分位数不再具有任何边际覆盖率意义。换句话说，**CP Judger 在实现上退化成了一个"用邻域自适应确定的启发式阈值"，它可能工作得很好（消融里确实比朴素阈值好 8 个点），但它不是保形预测，它享受不到论文反复援引的那个统计保证。** 而这个保证，恰恰是本文相对 MDAgents（同样做自适应路由，但用 LLM 自判难度）声称的全部理论优势所在。
更糟的是，论文 4.3 节白纸黑字写了"CP Judger 的行为将在敏感性分析部分用覆盖率、平均预测集合大小等标准保形预测指标进一步分析"，而 5.4 节**根本没有报告覆盖率，也没有报告集合大小**，只画了 α 对准确率和耗时的曲线。这意味着读者无从判断：实测覆盖率是否真的达到 1−α？有多少比例的样本被升级了？集合大小分布长什么样？这三个数字是评估这篇论文核心模块的**最基本证据**，一个都没给。另外，关键超参 N（校准集大小）在正文、实现细节和附录中**通篇未曾给出**——而在 α=0.05 下，有限样本修正要求 N ≥ 19，否则分位数根本无定义，可见这个参数对系统行为影响极大。
**要让这篇文章的核心主张成立，作者必须：(1) 报告实测经验覆盖率与预测集合大小分布，并与名义 1−α 对照；(2) 补一个使用固定全局校准集（满足可交换性）的对照实验，说明动态校准到底是提升了还是仅仅牺牲了理论保证；(3) 公布 N 及其敏感性分析。** 在此之前，最诚实的表述应该是"a confidence-gated adaptive framework"，而不是"conformal-guided with rigorous statistical guarantees"。

## 3：相关工作

**MDAgents（NeurIPS 2024，MDAgents: An Adaptive Collaboration of LLMs for Medical Decision-Making）**：ConfAgents 最直接的竞争对手，也是它"我们是第一个系统性研究医疗多智能体效率-准确率权衡"这一新颖性声明最大的威胁。MDAgents 同样做自适应协作——它先判断医学问题的复杂度（低/中/高），低复杂度直接单模型解决，中等启动多智能体协作，高复杂度才召集完整的 MDT 式专家团队。二者的差异只在"由谁来判断难度"：MDAgents 让 LLM 自己判，ConfAgents 换成 CP 判据。所以这篇文章更准确的定位应该是"MDAgents 的路由器改进"，而不是一个全新的问题。表 2 里 MDAgents 的耗时也确实是所有多智能体基线里最低的，侧面印证了这一点。

**MedAgentsBench（arXiv:2503.07459, Tang et al., 2025）**：ConfAgents 的评测底座就来自它——Test-Hard / Test-Normal 子集的划分策略是照搬的。这个 benchmark 的动机很值得注意：现有医学 QA 数据集上强模型已经接近饱和，简单题占比过高，导致各种 agent 框架之间的差距被稀释、看不出真实能力差异。它专门筛出需要多步推理的困难题，用来评测 thinking 模型和 agent 框架。做 medical agent 的话，这是目前更能反映方法真实水平的评测集，比在完整 MedQA 上刷分有意义。

**Large Language Model Validity via Enhanced Conformal Prediction Methods（NeurIPS 2024, Cherian, Gibbs & Candès）**：ConfAgents 引用的保形预测方法学基础之一，来自 Candès 组。它关心的是如何给 LLM 的**开放式生成**提供有效性保证——通过对生成内容中的断言（claim）做保形式的筛除，在保证事实性的前提下尽量保留信息量，并引入了条件化的、更贴合具体输入的覆盖率保证。这条线正在解决的问题，恰恰就是 ConfAgents 绕开的那个：**如何在"针对具体输入自适应"和"仍然保有统计保证"之间取得平衡**。想沿着这个方向做的话，从这条线切进去，比从多智能体那条线切进去更有理论纵深。
